# Size a talk's deck for questions, not for the clock

On 2026-09-30, while I was revising a 29-slide deck for a 30-minute lab group-meeting talk (the LLM-use talk), the
user said: "30분짜리 발표 플랜인데 ppt 너무 많음. 보통 발표 끝나기 전에 질문들이 많이 들어와서 극단적으로는 10장짜리
슬라이드로 1시간 발표한 적도 있음." In this lab the audience interrupts with questions throughout, so the real speaking
time per slide is far longer than a slide-per-minute rule assumes.

## How I apply it

- For a 30-minute talk, plan about 12–14 main slides; for shorter slots scale down from there. Never one slide per
  minute.
- No section-divider or agenda slides that only cost time; merge related points into one slide.
- Move supporting detail (extra figures, specs, benchmarks) into a clearly marked **Backup** section after the closing
  slide, so it is at hand when a question comes but does not lengthen the talk.
- Ask for the slot length when it is unknown, and state the slide count I chose and why.
