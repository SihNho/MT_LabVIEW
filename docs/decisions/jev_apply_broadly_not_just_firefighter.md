# "Jev를 적용하자" means the whole table, and it is meant to cut cycle time NOW

On 2026-09-22 the user asked to restart the runner "with the Jev structure updated" (*"그렇게 Jev 구조 갱신한 상태에서
러너 시작해보자"*). I wired only the firefighter veto (the one insertion with a finished measurement) and left the
time-saving insertions (#1 review discharge, #2 log triage, #5 NEXT quality, #6 prior-art re-ask prevention) as
"measure later". Forty minutes into the next cycle the user asked why it was still slow and then:

> *"전에 한 이야기 다 어디로갔어? Jev를 소방수에 한정하지 말자고 하지 않았나"*

## How I apply it

- When the user approves a plan with several items, "do it" covers the items, not the one that happens to be
  ready. If an item needs a measurement first, run the measurement immediately (in parallel, it costs cents), do
  not park it.
- The purpose of Jev here is cycle time. Insertions that remove peer reviews and session reading (#1, #2, #6)
  come first, even before the ones that are easiest to wire.
- Measurement still precedes switching a gate to "active", but it is done right away and reported with the
  wiring, not offered as a future step.
