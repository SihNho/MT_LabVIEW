# Jev를 넣을 자리 — 사이클 시간 절약 계획

사용자 결정(2026-09-22): Jev 관련 장치는 "장치 금지"(09-18)의 예외. 목표는 **사이클 시간 절약**.
근거 측정(사이클 53~59, 522분): 판단 세션 자체 52% · 피어 리뷰 21%(12건, 건당 9분) · 빌드/진단 14% · 회고 6% · 사전 조사 5%.
첫 시험(`tools/bench/jev_trial.py`, 40쌍): Jev 92.5% vs 정규식 77.5%(정정 라벨), Brier 0.059, 0.52초/호출, 40회 $0.0032.

## 공통 원칙

- Jev는 **판별**(선택·점수·예/아니오)만 한다. 생성·이미지·VI 상태 판독은 대상이 아니다.
- 모든 호출은 `tools/jev.py` 한 곳을 거친다(키는 `TYPESAFE_API_KEY` 환경 변수만, 재시도, 토큰 집계, 절대 키 미기록).
- 자리마다 **라벨 세트(≈40)로 먼저 측정**하고, **보조 신호**(`JEV-…` 로그 줄, 기존 규칙을 덮지 않음)로 시작해 몇 사이클 일치를 본 뒤 승격한다.
- 확률 0.3~0.7은 "모름" → 기존 경로. 그 밖에서만 행동.
- 기존 규칙과 충돌하지 않는다: 리뷰 면제는 "같은 질문은 archive를 먼저 보고 재질의하지 말 것"(CLAUDE.md §5)의 기계화이지 리뷰 폐지가 아니다.

## 넣지 않는 곳

GUI 캡처 비교(이미지 불가) · 배선·이동의 정오 판정(VI 상태를 텍스트로 줄 수 없음) · 가설 리뷰·회고 본문·결과 리뷰(논증이 산출물) · 레시피·계획 작성(생성).

## 순서와 예상 효과

1. #3(완료) + #1 → 리뷰 시간 절반. 2. #2 → 세션 읽기 단축. 3. #5, #4 → 낭비 사이클 방지. 4. #6~#9.
현실적 목표: 사이클당 15~25%. 그 이상은 "사이클당 피어 리뷰 최대 1건" 같은 규칙 변경이 필요하며, 그것은 리뷰 품질과 맞바꾸는 사용자 결정이다.

## 각 자리의 도입 절차(공통)

라벨 세트 작성 → `tools/bench/jev_<자리>.py` 한 번 실행(bgrun, ≤$0.05) → 정확도·Brier·불일치 목록 → 보조 신호로 삽입 → 3사이클 관찰 → 승격 또는 철회. 각 단계는 `docs/cycle27-plan.md` Pre-decided에 한 줄로 기록.
