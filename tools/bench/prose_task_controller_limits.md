[배경]
- 원본 LabVIEW VI의 자석(PI) 상한·하한은 모터 명령 앞의 coerce가 아니라 패널 컨트롤 `Trans Step (mm)`의 입력 범위(0 ~ 40.84)였음. 사용자가 실물에서 확인: 45 입력 → 40.84에서 멈춤, -50 입력 → 컨트롤 값이 0으로 바뀌고 자석 0. 이 컨트롤은 이름과 달리 절대 목표 위치.
- 컨트롤 입력 범위는 사람이 패널에 직접 입력할 때만 깎음. VI 서버나 배선으로 들어오는 값은 깎지 않음 → 무인 하네스가 값을 써넣는 경로에는 보호가 없었음.
- 그래서 컨트롤러 자체에 리밋을 넣기로 함 (사용자 결정).

[PI C-863.11 (자석, COM3)]
- 컨트롤러의 기본 이동 범위: TMN 0, TMX 52 mm. 40.94(문서상 상한)도 52도 컨트롤러는 막지 않음.
- 리밋 명령: `SPA 1 0x15 39.0`(상한), `SPA 1 0x30 0.0`(하한). RAM에만 저장, 컨트롤러 전원을 끄면 사라짐. 비휘발성 저장(`WPA`)은 하지 않음. 컴퓨터 전원과는 무관.
- 실측 1 (14:50): 설정 후 TMX?=39, TMN?=0 확인. `MOV 1 40` → 거부, 에러 5, 위치 0 그대로. 그러나 에러 5는 "축 미참조/서보"라서 리밋 때문인지 불명.
- 원인: 축이 참조 모드 켜짐(RON 1) + 미참조(FRF 0) 상태. 사용자 판단 "초기화 없이 바로 종료해서 그런듯". 원본 VI는 자동참조(Autoreference? 1=Y)를 0으로 두고 현재 위치를 정의해서 쓰는 방식이므로, 같은 방식으로 복구: `RON 1 0`, `POS 1 0` (움직임 없음).
- 실측 2 (14:51): 복구 후 `MOV 1 40` → 에러 7(PI_CNTR_POS_OUT_OF_LIMITS), 위치 0 그대로. `MOV 1 38.5` → 이동, 38.5 도달. `MOV 1 0` → 복귀. 컨트롤러 리밋 동작 확인.
- 추가 발견 (15:37 하위 세션 실측): 리밋 쓰기 명령 `SPA` 자체가 축의 참조 상태(FRF)를 지움. 그래서 훅이 리밋을 쓴 뒤 `RON 1 0` + `POS 1 <방금 읽은 같은 값>`으로 참조를 복구하도록 수정 (좌표 이동 없음).
- 최종 실측 (15:58, 10/10 통과): 세션 시작 훅 → 리밋 되읽기 일치, FRF?=1 · `MOV 1 5` 이동 · `MOV 1 40` 컨트롤러가 에러 7로 거부, 위치 5 그대로 · `MOV 1 0` 복귀 · 세션 종료 훅 → TMX 52로 해제 확인 · 다시 설정하여 리밋 켜진 채 종료.

[ASI 스테이지 (COM4)]
- 명령: `SL X=.. Y=..`(하한), `SU X=.. Y=..`(상한), 단위 mm, 절대좌표(`W X`로 읽는 좌표와 같은 좌표계). 범위 밖 이동은 명령을 받아들이되 스테이지가 리밋에서 멈춤. 원점 이동(`!`)과 조이스틱도 걸림. 전원을 껐다 켜도 자동 유지(SAVESET 불필요).
- 이전 값: X,Y 모두 ±500 mm(사실상 없음), Z ±0.075 mm.
- 사용자 지시 "지금 값을 기준으로 +- 2mm": 현재 X -1.8475, Y -2.7744 mm 기준으로 `SL X=-3.8475 Y=-4.7744`, `SU X=0.1525 Y=-0.7744` 기록. 되읽기 X -3.847494/0.152497, Y -4.774393/-0.774402 (반올림 0.5 µm). 위치 변화 없음. Z는 건드리지 않음.
- 해제 명령: `SL X=-500 Y=-500`, `SU X=500 Y=500`.
- 최종 실측 (15:58): `M X=-16475`(+0.2 mm) 이동 후 복귀, 오차 2단위(0.2 µm). `HOME X`는 소프트웨어 게이트가 거부(전송 안 됨).
- 주의: 리밋이 절대좌표라 좌표 원점이 바뀌면(`HERE`/`ZERO`, 또는 원본 VI가 시작 시 원점을 다시 잡는 경우) 울타리가 통째로 옮겨짐. 그래서 원점 명령은 소프트웨어에서 영구 금지. 원본 VI 시작이 원점을 바꾸는지는 다음 무인 실행 뒤 `W X` 되읽기로 확인 예정.

[소프트웨어 구조 (사용자 결정 "지금 게 더 좋다")]
- `tools/motor_gate.py`: 스크립트 자체의 숫자 범위 판정(0~39, ±1 mm)과 기준점 파일은 삭제. 남긴 것: 리그 상태 확인(실험중이면 전부 거부), 원점·영점·참조·저장 명령 금지, 명령이 나가는 통로 하나.
- 새로 넣은 것: `--session start`(컨트롤러에 리밋 기록 + 되읽기 확인, 불일치면 거부) / `--session end`(해제 + 되읽기). 이동 명령 전송 직전에 같은 포트 연결 안에서 리밋을 되읽어 파일(`tools/bench/motor_limits.json`, 사용자가 편집 가능)과 다르면 전송 거부.
- 자체 시험(포트 안 열고) 76/76 통과, 실물 시험 10/10 통과.
- 비정상 종료 시 리밋은 켜진 채 남음(안전한 방향). 다음 세션 시작 훅이 다시 맞춤.

[현재 상태]
- 자석 0 mm, ASI 기준점(+0.2 µm 이내). PI 리밋 0~39 RAM에 켜짐, ASI ±2 mm 영구. LabVIEW 없음. 원본 VI 해시 변동 없음(C39F36E0…).

[남은 것 / 사용자가 알아둘 것]
1. PI 상한 39는 원본 패널 상한 40.84보다 낮음. 실험에서 39 이상을 쓰면 컨트롤러가 에러 7로 거부하고 원본 VI에 에러가 남. 실험 최대 위치에 맞춰 `motor_limits.json` 값을 바꿀 수 있음.
2. 현재 위치를 0으로 정의하는 방식은 컨트롤러의 0이 물리적 0과 같음을 증명하지 못함(원본도 같은 방식). 자석이 0에 있을 때의 물리적 위치를 눈으로 확인해 두면 그것이 기준.
3. 원본 VI 시작이 PI 리밋(TMX)이나 ASI 원점을 바꾸는지: 다음 무인 실행 뒤 `TMX?`, `W X` 되읽기로 확인.
