## D1 — 첫 납품: "획득·트래킹·저장·정지" 네 루프 (마스터 플랜 1.1 / 1.2 / 1.7 / 1.8 / 1.9)
### 1.1 획득 루프
- 원본의 프레임 루프에서 트래커 호출을 **빼낸** 것. 카메라에서 최신 버퍼(`Buffer Number Mode = Last`)를 읽어 **미리 할당된 이미지 풀(20슬롯)** 의 빈 슬롯에 복사(측정 0.12 ms)하고, 슬롯 번호 + 버퍼 번호를 작업 큐에 넣는다. 빈 슬롯이 없으면 그 프레임은 **건너뛴다** — 카메라를 절대 기다리게 하지 않는다(사용자 규칙: 카메라는 free-run, PC는 읽기만).
- 슬롯은 "빈 큐"와 "작업 큐" 두 개로 관리되어 FREE → FILLING → OWNED로 돌고, 모든 종료 경로(정상·커널 에러·큐 타임아웃·종료·저장 에러)에서 슬롯이 **정확히 한 번** 반환되어야 한다. 한 번 새면 획득이 굶고, 두 번 반환되면 같은 메모리를 둘이 쓴다.
- 카메라 계약(`ExposureAuto = Off`, 노출 ≈ 5,556 µs)은 세션이 열리는 startup frame(diagram 87)에서 쓰고 되읽어 기록한다 — 세션을 열면 값이 리셋되므로 외부에서 미리 설정할 수 없다.
- 수용: 되읽은 노출값이 기록에 남고, 슬롯 장부가 맞음(가져간 수 = 반환한 수).
### 1.2 트래킹 루프
- 작업 큐에서 슬롯을 꺼내 커널 한 번 호출 → 결과에 버퍼 번호를 붙여 결과 큐로. 커널 후보는 프레임별 호출 가능한 3종: `PARALLEL_kernel_v3clean.vi`(200프레임×3에서 원본과 비트 동일), `GPU_kernel_v1.vi`(200프레임×3에서 x,y 4.9e-7 px / z 2.9e-6 µm, 0 flip; 10,043 프레임 전체는 미실행), `TRACK_kernel_v1.vi`(CPU/GPU 선택형).
- 수용: 픽스처에서 원본과 수치 동일(x,y ≤ 1e-6 px, z ≈ 1e-4 µm — 사용자 허용치). GPU 값은 특정 GPU 기종에서만 재현 보장이라, 기계가 바뀌면 재측정.
- 트래커 어느 것으로 시작할지는 사용자 결정 대기(아래 질문 2).
### 1.7 저장 루프
- 결과 큐를 소비하는 무손실 FIFO. 원본처럼 끝에 한 번이 아니라 **실행 중 계속** 파일에 쓴다. 큐 타임아웃과 error-1122 종료 경로는 이미 설계돼 있음(restructure-plan-4.6.md:65-68).
- 수용: 계산된 모든 결과가 순서대로 파일에 있음.
### 1.8 프레임 계정
- 원본의 버퍼 장부 subVI(#6810)를 재사용할지 새로 쓸지 문서로 결정. 수용: 버퍼 번호 추적과 이 VI의 숫자가 일치하거나, 불일치가 설명됨.
### 1.9 정지·종료
- 정지 조건은 **각 루프 안에서** 읽는다(밖에서 와이어로 넣으면 루프 시작 전 한 번만 읽히는 함정). 순서는 항상 "사용자 루프 정지 → 큐 비우기 → 큐 해제"(안 그러면 error 1122). Abort로 죽인 뒤 다음 시작에서 남은 큐·이미지·카메라 세션·파일 refnum을 치우는 코드 포함.
- 수용: 모든 루프가 내부 Boolean으로 멈추고, 1122 없이, 고아 큐·이미지·세션 없이 정지; Abort 후 재시작이 깨끗함.
### D1이 끝나면 사용자가 보는 것
- 카메라를 라이브로 돌리며 트래킹하고, **실행 중에** 파일이 쌓이고, 버튼으로 깨끗이 멈추고 다시 시작되는 VI 하나. 모터·스케줄러·초점·화면은 아직 원본 방식이거나 빠져 있음 → 비드 실험은 아직 못 함(리그 분해 상태라 어차피 비드 없음).
### D1 수용 게이트
- N1 픽스처 수치 동일 / F1 카메라 라이브 5분 + 파일 생성·재열기 / F2 정지·재시작 깨끗 / 슬롯·큐 고수위 평탄, 핸들 수 평탄.

## D2 — 나머지 세 루프 + 화면 (마스터 플랜 1.3 / 1.4 / 1.5 / 1.6), 그 뒤 Phase 2 드라이런
### 1.3 스케줄러 루프
- 실험 사이클 상태기계. 모터 루프에 목표값 4개(속도·힘 등)를 넘기는 **전달 방식이 미결**: (a) 네 값을 한 번에 쓰고 한 세트로 읽는 lock-step 발행(이미 검증된 패턴) 또는 (b) 클러스터 typedef를 하나 만들어 클러스터 로컬/큐. 루프 3을 만들기 직전에 정하고 기록. 수용: 모터가 절반만 갱신된 목표 세트를 절대 읽지 않음.
### 1.4 모터 루프
- 모터 읽기·제어를 프레임 루프 밖으로. 로터는 **`SetCommand_signed.vi`, 부호 포함 하드웨어 숫자 그대로**(사용자 결정 2026-09-16). 로터 카운터는 0 기준(옛 100,000 baseline 없음). 수용: 명령 발행·되읽기 동작, 호출은 기존 경로와 동일하고 값만 다름.
### 1.5 ASI 초점 루프
- VISA 세션을 **독점** 소유. 프레임 경로와는 non-blocking 핸드오프로만 연결(사용자 규칙 1c: 프레임 경로에 시리얼 없음). 매 프레임이 아니라 N프레임마다. 수용: 프레임 루프에 VISA 호출 0.
### 1.6 화면 루프
- 10~20 Hz로 제한 + Defer Panel Updates, Image Display 사용(Picture보다 빠름, 측정됨). 수용: 화면 갱신이 프레임 예산에 들어가지 않음.
### D2 뒤 Phase 2 드라이런(리그 없이)
- 프레임 계정(버퍼 번호 연속 또는 명시적 gap), 카메라 비게이트(트래커를 일부러 느리게 해도 카메라 cadence 불변), 정체성(결과 N이 프레임 N의 픽셀로 계산됨 — 사용자가 낸 오염 검사), 시리얼로 인한 손실 0(계측으로 검증), 백프레셔(저장·디스크를 몇 분 느리게 해도 획득은 건너뛰기로만 대응), 슬롯 불변식 free+queued+processing=풀 크기 연속 검증, 고수위·핸들 수 평탄.
### D2가 끝나면 사용자가 보는 것
- 일곱 루프 VI. 90 Hz 드라이 배치에서 모터 명령 발행·되읽기, 실제 데이터 파일, 깨끗한 정지·재시작, 저장 파일 재검증까지 — 성과 리뷰가 "감독 하 무리그 파일럿"으로 사용자에게 넘기라고 한 상태. 그 다음이 CPU 병렬 상위 VI.
