## 1. Strongest reason the claim is wrong

The tool can't find the recipe's own base graph, and this has happened before.
- `find_graph` only searches `tools/bench/graph_*.json` and `tools/bench/sim/*/graph_*.json` (`tools/stage_prerun.py:165`).
- The graph that belongs to the Part-A input is `tools/bench/par1359_95_graph.json`. Its header carries the S1 md5 `3e3d23ce…` (`par1359_95_graph.json:2-3`), but its file name doesn't start with `graph_`, so `find_graph` never sees it.
- The recipe's plan already names this graph as its base (`diag_c106c_peek.log:125`), and the recipe says its input is "named by the plan's base graph" (`tools/recipes/stage_d1_disp.py:1`). The pre-run still ignores that.
- The function's own docstring records the same failure twice before: "every `--prerun` launched without `--graph` failed gate X1 in cycles 85 and 86 … re-launched by hand with `--graph`" (`stage_prerun.py:160-162`).
- Every past Part-A or full pre-run of this recipe was launched by hand with `--graph tools/bench/par1359_95_graph.json` (`diag_c103_prerunA.log:1`, `diag_c103b_prerunA.log:1`, `diag_c103c_prerunA.log:1`, `stage_d1_disp_prerun*.log:1`).

Case 106 is the third occurrence of the "`--prerun` without `--graph` fails X1" pattern. Passing `--graph` in the test hides the gap instead of closing it. Under CLAUDE.md this counts as `repeated-failure-class`, not a one-off test bug.

## 3. Alternative explanations

The code path makes the graph gate the most likely cause:
- With `graph=None`, `_graph()` calls `find_graph(3e3d23ce…)`, which returns `None` (`selftest_stage_prerun_graphload.py:89`).
- The `start()` gate then fails as fatal (`stage_prerun.py:639-642`).
- The Part-B cases pass because the Part-B input's md5 does match `sim/disp/graph_dispA_step33.json`.

But the c103 control is not a clean control. It differs from c106c in two ways, not one:
- It passes the graph to `prerun()`.
- It also puts `--graph GRAPH` into `sys.argv` (`selftest_stage_prerun_c103.py:30`); c106c does not (`c106c.py:41`).

So these causes are not yet ruled out:
- (a) Something in the dry run or the refactored `stagexec` Part-A path reads `sys.argv`.
- (b) A STUB-LIMIT or "body did not reach its end" failure that only appears in Part-A mode without a graph.

I find both unlikely, but the recorded evidence doesn't exclude them.
