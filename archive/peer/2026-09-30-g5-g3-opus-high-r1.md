## Question

In NI-IMAQdx (C function IMAQdxGetImageData, or the LabVIEW IMAQdx Get Image2 VI), what numeric value does each buffer-number mode (Next, Last, BufferNumber, Every, LastNew) have, and which of these modes returns immediately without waiting for a new frame from the camera?

Search the web and cite the URL of every source you used.

## Answer

I could only partly answer this. The public sources give numbers for three of the five modes. For which mode returns immediately, the only clear statement is about **Last**.

## Numeric values

| Mode | Value | Source |
|---|---|---|
| `IMAQdxBufferNumberModeNext` | **0** | enum declaration order |
| `IMAQdxBufferNumberModeLast` | **1** | enum declaration order |
| `IMAQdxBufferNumberModeBufferNumber` | **2** | enum declaration order |
| Every | **not found** | — |
| LastNew | **not found** | — |

A public copy of `NIIMAQdx.h` declares the enum with no explicit values, so C numbers them 0, 1, 2 in order. The only other member is `IMAQdxBufferNumberModeGuard = 0xFFFFFFFF`. The same header shows the prototype `IMAQdxGetImageData(IMAQdxSession id, void* buffer, uInt32 bufferSize, IMAQdxBufferNumberMode mode, uInt32 desiredBufferNumber, uInt32* actualBufferNumber)`. NI's own .NET wrapper declares the same three members (`Next, Last, BufferNumber`) with nothing more.
- https://github.com/wpilibsuite/nivision/blob/master/cpp/include/Vision/NIIMAQdx.h
- https://raw.githubusercontent.com/ni/imaqdx-dotnet/master/src/Internal/ImaqdxBufferNumberMode.cs

**Every and LastNew:** I found no source that gives their numbers. Both headers I could read are older and don't define them. Newer IMAQdx versions do have these modes (a forum thread lists "Next, Newest, Oldest, Every, Last New, None"), but I won't guess their numbers. They may well follow as 3 and 4, but nothing I found confirms that. The reliable check is the `NIIMAQdx.h` from your installed driver, or the ring/enum constant on the Get Image2 VI's buffer number mode input in LabVIEW.
- https://forums.ni.com/t5/Machine-Vision/Random-Get-Image2-vi-timeout-error-1074360293-during-a-GigE/td-p/3805397

## Which mode returns immediately

- **Last is the only one documented as not waiting.** NI's wording, quoted in the forum: "The driver does not wait for the next buffer but instead returns the last acquired buffer." It can return the same image again if no new frame has arrived.
- **Next waits.** "The driver waits for the next acquired buffer." This is the default.
- **BufferNumber waits.** It "specifies an exact buffer number to wait for," so the VI blocks until that buffer has been acquired.
- **Every:** "Returns all sequential images in memory." A forum answer says it keeps track of the buffers already read and returns the next one without waiting for a new frame, if that buffer is already there. It's reasonable to assume it waits when it has caught up, but no source says so.
  - https://forums.ni.com/t5/Machine-Vision/Buffer-Mode-quot-Next-quot-and-quot-Every-quot-in-IMAQdx-Extract/td-p/4079556
  - https://natinst.public.imaq.general.narkive.com/OyB8ZFv2/quot-buffer-number-in-quot-confusion-with-imaqdx-get-image
- **LastNew: not settled.** NI has a knowledge-base article on exactly this ("Buffer Number Mode 'Last' And 'Last New' Differences"), but I couldn't open it because of a certificate error. The name suggests it returns the latest frame only if you haven't already read it, and otherwise waits for a new one. That is a guess. One search summary claimed this behaviour, but the text it used came from a different NI product (Vision Builder's "Immediate" mode), so I'm not counting it.
  - https://knowledge.ni.com/KnowledgeArticleDetails?id=kA03q000001DwvoCAC&l=en-US

I also couldn't read NI's official Get Image2 and IMAQdxGetImageData reference pages (one returned only site navigation, the other a 403):
- https://www.ni.com/docs/en-US/bundle/ni-imaqdx-vi-ref/page/ni-imaqdx_vi_reference/imaqdx_get_image2.html
- https://www.ni.com/docs/en-US/bundle/ni-imaqdx-c-api-ref/page/ni-imaqdx_function_reference/imaqdxgetimagedata.html

**Short answer:** Next = 0, Last = 1, BufferNumber = 2. Every and LastNew have no public number I could confirm. **Last** is the documented mode that returns immediately without waiting for a new frame.
