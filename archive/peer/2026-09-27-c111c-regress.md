## The gate the 22 tests do not reach: the RUNNER_MODULES deny-list

`launchunit.py:9-13` treats every `.py` after `py -m <module>` as an argument unless the module is on `RUNNER_MODULES`. `launched_py` (launch gate) and `drop_module_args` (card flags) both follow that rule, and the docstring at `launchunit.py:34` says so explicitly.

The deny-list is a closed list over an open set, so it is not fail-closed. Modules that execute their script argument but are missing from the list include:
- `python -m streamlit run your_script.py` runs the script ([Streamlit docs](https://docs.streamlit.io/develop/concepts/architecture/run-your-app)).
- `mprof run` runs it (the list has `memory_profiler`, not `mprof`; [memory_profiler #343](https://github.com/pythonprofilers/memory_profiler/issues/343)).
- From recall, not checked here: bokeh/panel `serve`, `nox -f`, `doit -f`, `locust -f`, `manim`, `bpython`.

For `py -m mprof run tools/recipes/stage_x.py`:
- **Launch gate:** finds no launch unit, so no dry/pre-run is required.
- **Card flags:** the path is dropped. HEAD's `protocol._launched_scripts` counted every existing `.py` after a `py` token, so it would have refused this.
- **Stop record:** stays `build`, but that only matters while an undisposed record exists.

So two of the three gates are weaker than HEAD on this shape. `selftest_c111c_launchunit.py` only tests listed runners (pdb, trace, pytest), so nothing detects it.

A smaller point: `-m` puts the **current directory** first on `sys.path` ([Python docs, `-m`](https://docs.python.org/3/using/cmdline.html)). `cd_only_to_root` only looks at `cd` inside the command. If the shell's working directory persists from an earlier call, a shadow `pyflakes.py` in that directory would be credited as read-only. I did not check whether the hook reads the payload's `cwd`.
