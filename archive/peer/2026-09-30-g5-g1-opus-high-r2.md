## Question

In LabVIEW VI Scripting (VI Server), which property of a Wire object reports whether that wire is broken, and what is that property's unique ID string (the hex ID used when the property is set with Allow Alternate Names = FALSE)? Also say what kinds of wire problems that property does and does not flag.

Search the web and cite the URL of every source you used.

## Answer

I could only fully answer the first part: the property and its ID. The sources don't settle which wire problems it does and doesn't flag.

## 1. The property
It's the **Wire** class property **Is Broken?**. Its short name and data name are both `Broken?`. It is a read-only Boolean in VI Scripting, and it isn't available in the Run-Time Engine or on real-time targets. It is documented from LabVIEW 2018.
Source: https://labviewwiki.org/wiki/Wire_class/Is_Broken%3F_property

## 2. The ID string
The Property ID is **`6371004`**. The Wire class ID is 16439.
Sources: https://labviewwiki.org/wiki/Wire_class/Is_Broken%3F_property and https://labviewwiki.org/wiki/Wire_class

`6371004` is hex, meaning 0x06371004. The Wire class table numbers its properties from `6371000` up to `637100E`, so the IDs can't be decimal. The Property class uses the same format, for example `636F80E`.
Source: https://labviewwiki.org/wiki/Property_class

**Caveat on "Allow Alternate Names = FALSE":** The `Set Properties()` method on the Property class takes an `ID Strings[]` array and an optional `Allow Alternate Names? (F)` Boolean. Source: https://labviewwiki.org/wiki/Property_class/Set_Properties()_method

None of the sources I found says exactly which string that method expects when alternate names are off. A related page adds some doubt. It describes a separate "Unique ID string" that is "consistent across all versions and locales of LabVIEW", and says that "Properties without a Unique ID string return an empty string." Source: https://labviewwiki.org/wiki/Property_class/All_Supported_Properties_property

So `6371004` is the documented hex property ID. I could not confirm that it is also the "Unique ID string" `Set Properties()` wants. Reading **All Supported Properties** on a Wire-class Property Node would show the actual value.

## 3. What it does and doesn't flag
The only official-style description is that it "Returns TRUE if the wire is broken or in a bad state." Source: https://labviewwiki.org/wiki/Wire_class/Is_Broken%3F_property

For context, NI lists these usual causes of broken wires:
- incompatible data types
- a wire with more than one data source
- a wire with no data source
- a wire not connected to anything
- unwired or overlapping tunnels

Source: https://www.ni.com/docs/en-US/bundle/labview-nxg-g-programming-api-overview/page/troubleshooting-broken-wires.html (this page is for LabVIEW NXG). Related LabVIEW error pages: https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/errors/wire-has-multiple-sources.html, https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/errors/wire-has-no-source.html, https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/errors/wire-is-not-connected.html (I only have their titles; the pages' content didn't load).

No source I found says which of these cases set **Is Broken?** to TRUE. None says what it misses either, such as coercion dots, hidden wires, or errors elsewhere in the VI. Anything I said on that would be a guess. Testing each case with scripting would settle it.
