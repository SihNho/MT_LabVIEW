QUESTION:
When LabVIEW is automated from another program through its ActiveX (COM) server, the VirtualInstrument object is used to control a VI. Which VirtualInstrument property tells the client whether that VI is broken (cannot run), what numeric values can that property take and what does each mean? Does the ActiveX VirtualInstrument interface also expose a separate 'is broken' Boolean?

KNOWN ANSWER (verified on the machine / vendor files):
The ExecState property (execution state enum): 0 = bad / broken (eBad, broken run arrow), 1 = idle / runnable (eIdle), 2 = running as top-level VI (eRunTopLevel), 3 = running as a subVI / reserved for running (eRunning). There is no separate IsBroken member on the ActiveX VirtualInstrument interface; ExecState = 0 is how brokenness is read.
KEY POINTS: property ExecState; 0 = broken (eBad); 1 = idle/runnable; 2 and 3 = running; no separate IsBroken member

The property is **`ExecState`**, which returns an **`ExecStateEnum`**. The ActiveX VirtualInstrument interface has **no separate "is broken" Boolean**. A client finds out that a VI is broken by checking `ExecState == eBad (0)`.

**1. The property.** `ExecState` is listed among the VI Properties (ActiveX) of the VirtualInstrument class. Its description is "indicates the execution state of the VI", and it is used as `object.ExecState`, returning `ExecStateEnum`.
- https://rajsite.github.io/unofficial-lvdocs/axprop/VirtualInstrument_Class.html
- https://documentation.help/NI-ActiveX-LabView/ExecState.html (I only saw this in a search snippet; the page itself returned 403)
- https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/activex/vi/execstate.html (NI's official page; it didn't render for me, so I couldn't read it directly)

**2. The values of `ExecStateEnum`** (https://rajsite.github.io/unofficial-lvdocs/axprop/ExecStateEnum.html):

| Value | Name | Meaning (quoted) |
|---|---|---|
| 0 | `eBad` | "VI has errors; it cannot run." |
| 1 | `eIdle` | "VI is not running, but the VI is in memory." |
| 2 | `eRunTopLevel` | "VI is running as a top-level VI." |
| 3 | `eRunning` | "VI is running as a subVI." |

- The VI Server property `Execution.State` uses the same 0–3 numbering: Bad, Idle, Run top level, Running. For value 3 its wording is "VI is reserved for execution by one or more active top-level VIs." (https://labviewwiki.org/wiki/VI_class/Execution.State_property)
- Two sources show these names and numbers in real client code:
  - A C# client compares against `ExecStateEnum.eIdle`, `eRunning` and `eRunTopLevel` (https://shadow.nd.rl.ac.uk/SECI/html/LabViewApp_8cs_source.html).
  - An open-source LabVIEW MCP project reports a broken VI as "execState 0" and a working one as "execState 1" (https://github.com/Zuehlke/labview-mcp/pull/60).

**3. Is there a separate "is broken" Boolean?** No, based on the one property list I could read. That list for the VirtualInstrument class has no `IsBroken`, `Broken` or similar property. Its Booleans that start with "Is" are `IsCloneVI`, `IsProbe` and `IsReentrant`, and none of them is about being broken (https://rajsite.github.io/unofficial-lvdocs/axprop/VirtualInstrument_Class.html).

This comes from an unofficial mirror of NI's help, and I couldn't tell which LabVIEW version it matches. NI's own ActiveX pages load their content with JavaScript and came back empty when I fetched them, so I couldn't check the list against the current official reference. It's possible that a newer LabVIEW version added a Boolean. I found no evidence of one.

**Caveat:** a result of `eBad`/"Bad" doesn't always mean the VI's code is broken. In one NI forum thread, a VI that was running in another project showed as "Bad". The explanation given was: "It's bad because it's locked, because it's reserved in another instance." (https://forums.ni.com/t5/LabVIEW/Running-top-level-VI-indicated-as-bad-by-exec-state/td-p/4183251)
