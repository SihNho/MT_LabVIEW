## Question

In Windows PowerShell 5.1, when the standard output of a native executable is captured inside PowerShell (for example $x = & prog.exe | Out-String), which setting determines the character encoding used to decode those bytes, and what do you set so that UTF-8 output is decoded correctly?

Search the web and cite the URL of every source you used.

## Answer

**The setting is `[Console]::OutputEncoding`.** PowerShell uses it to decode the bytes a native program writes to stdout when that output is captured. To get UTF-8 output decoded correctly, set it to UTF-8 before you run the program:

```powershell
$prev = [Console]::OutputEncoding
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$x = & prog.exe | Out-String
[Console]::OutputEncoding = $prev   # restore afterwards
```

**What the sources say:**

- **PowerShell team's own statement.** The PowerShell GitHub pull request #21219 says: "Currently PowerShell uses the value of `[Console]::OutputEncoding` to control what encoding is used when reading the output from a native application." https://github.com/PowerShell/PowerShell/pull/21219
- **Same fix, older blog post.** Keith Hill's blog covers a native program that prints UTF-8 without a BOM (byte-order mark), which PowerShell garbles. The fix it gives is `[System.Console]::OutputEncoding = [System.Text.Encoding]::UTF8`. It also says to save and restore the original value, because leaving it set to UTF-8 made other tools misbehave (it names the C# compiler). https://rkeithhill.wordpress.com/2010/05/26/handling-native-exe-output-encoding-in-utf8-with-no-bom/
- **`$OutputEncoding` is not the answer.** It covers the other direction. The 5.1 docs say it "Determines the character encoding method that PowerShell uses when piping data into native applications", and its default in 5.1 is ASCII. You only need to change it if you also pipe text *into* the program. https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_preference_variables?view=powershell-5.1
- **The 5.1 encoding docs don't settle it.** The 5.1 `about_Character_Encoding` page only says `$OutputEncoding` "affects the encoding PowerShell uses to communicate with external programs." It never says which setting decodes a native program's output. So the direct statement comes from the GitHub pull request and the blog, not from the 5.1 reference docs. https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding?view=powershell-5.1
- **Newer versions only.** PR #21219 adds a `$PSApplicationOutputEncoding` variable that controls this decoding in a narrower scope. It was merged into PowerShell 7's main branch in October 2025, after the 7.6 release branch was cut. It does not exist in Windows PowerShell 5.1. https://github.com/PowerShell/PowerShell/pull/21219
