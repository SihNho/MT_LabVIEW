The claim conflates two things. True and already known: **our `create_indicator` wrapper has no diagram parameter** (`gscript.py:2423-2439` sets `Class Name=""`, `index`, `index 2` and nothing else; `connect_ctl` is the same shape, `:983-988`). Not shown by any observation here: that the **route** needs a top-level index for the nested source. S3a's answer is that it does not — you make the indicator on a carrier *you* put on the top level, `move_in` the ControlTerminal, then wire it with the diagram-scoped verb.

Gate B1_c ("a TOP-LEVEL `Nodes[]` index exists for source #10686", `:102`) is a precondition on **our calling convention**, not on LabVIEW. The stage failed its own gate before touching the machine — `ExecState` at the stop was still 1 (`:106`).

## 2. Alternative explanations

**A/A2 — `Terminal.Create Indicator` was never invoked.** I opened the screenshot the watchdog saved and nobody read (`gscript_dialog_1789953467.png`):

> **Error 1055 occurred at Property Node in OpCreateIndicator_v0.vi** — LabVIEW: (Hex 0x41F) Object reference is invalid.

And it is not news: `gscript.py:2434-2437` records this same dialog on **all 20 calls** of `diag_s3a_ind_transport.log`, whose sweep (`:36-55`) hit `(25,·)` **and** top-level `(0,·) (1,·) (2,·)`, all returning empty. Not nested-specific.

**A/A1 — 1055 is the routine reading for an unwired terminal here.** `diag_c62_s3b_rows.log:93` shows `'wire': 0, 'errs': [0,0,0,1055]` on eight terminals of `#637` in a cold, unmodified VI at `ExecState` **1**. The error does not identify *which* input was Null; it does not distinguish "node_index 25 out of range" from "panel_index 115's ref was bad".

**"Top-level lists 0 nodes" is uncorroborated and internally inconsistent.** A structure *is* a Node; if `#536` held zero, `Diagram #686` (owner of While Loop `#637`, `:92`) would be unreachable from it. `Diagram.Nodes[]` is indeed non-recursive, but nothing says a VI's top level reads empty. One reader produced this — `node_labels`, `Class Name="Diagram"` (`gscript.py:587-594`) — while cycle 46 read the same diagram with a different reader and got `('TopLevelDiagram', 536)` (`stage_d1_s3a_focus_ind.py:84`), a **distinct class** and a plausible place for a `Diagram`-scoped traverse to return nothing. Either way it does not block the route: if the top level is empty, you put a carrier on it, which is what gate `N1_b` measured working, census 114 → 115 (`:87`).

**A/A3's raise is a broken post-condition — but the wire is not yet proven good.** `gscript.py:1794-1797` checks `exec_state != 1` **absolutely**; the timeline (`:124`) shows `ExecState` was already 0 at step 8, before the call. So that verb cannot pass as a mid-sequence step in *any* multi-step edit, and its advice ("revert the target") would have discarded real work. But its contract (`gscript.py:1765-1767`) says an **unwired source** makes it extend an unrelated wire → "connects more than one data source" → break. A/A3 called it in exactly that forbidden state. Two hypotheses survive, and **the log does not separate them**: 23499 is a proper source→indicator wire and the bare selector explains `ExecState` 0 (H_good), or it is a two-source wire — the condition `docs/NAMES.md:935-936` measured as `Is Broken? = True` (H_bad).
