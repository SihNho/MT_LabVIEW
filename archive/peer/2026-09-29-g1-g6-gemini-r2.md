## Question

On an NTFS volume in Windows, a file is deleted and a new file with the same name is then created in the same folder shortly afterwards. What creation timestamp does the new file have, and what is the mechanism called?

Search the web and cite the URL of every source you used.

## Answer

### Answer

1. **Creation Timestamp:** The new file inherits the **creation timestamp of the original (deleted) file**, rather than receiving the current system time.
2. **Mechanism Name:** **File System Tunneling** (also referred to as *File Name Tunneling* or the *NTFS Tunneling Cache*).

---

### Technical Details & Reasoning

* **Behavior:** When a file is deleted or renamed, the Windows file system (NTFS, FAT) temporarily caches its metadata (specifically the creation time and 8.3 short filename / long filename association) in memory per directory. If a file with the same name is created in that same directory within the tunneling cache window, the file system applies the cached creation timestamp to the newly created file.
* **Default Time Window:** **15 seconds** (configurable up to 71 seconds). If the new file is created after this window expires, it receives a normal current timestamp.
* **Purpose:** Implemented for compatibility with legacy applications and safe-save patterns (where an application saves by writing to a temporary file, deleting the original, and renaming the temporary file). Tunneling prevents the apparent creation date from shifting to the modification time on every save and preserves 8.3 short names.
* **Registry Controls:** Located at `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem`:
  * `MaximumTunnelEntryAgeInSeconds` (`REG_DWORD`): Cache lifespan in seconds (default: `15`).
  * `MaximumTunnelEntries` (`REG_DWORD`): Maximum cache entries (default: `1024`; setting to `0` disables tunneling).
