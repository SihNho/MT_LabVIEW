QUESTION:
In the LabVIEW NI-IMAQdx palette, what are the DEFAULT values of the 'Buffer Number Mode' input of IMAQdx Get Image2.vi and of the 'Wait for Next Buffer?' input of IMAQdx Grab2.vi when those inputs are left unwired, and what does that default mean for a display loop that runs slower than the camera?

KNOWN ANSWER (verified on the machine / vendor files):
Get Image2 defaults to Buffer Number Mode = Next and Grab2 defaults to Wait for Next Buffer? = Yes (TRUE); both wait for the next buffer in sequence. A loop slower than the camera therefore falls behind, the driver ring overwrites unread buffers and frames are missed; wiring Last (or No) returns the newest buffer without waiting and decouples the display rate.
KEY POINTS: Get Image2 default Next; Grab2 default Wait for Next Buffer = Yes; slow loop falls behind / buffers overwritten; Last decouples
