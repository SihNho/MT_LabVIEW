## Question

In NI-IMAQdx (C function IMAQdxGetImageData, or the LabVIEW IMAQdx Get Image2 VI), what numeric value does each buffer-number mode (Next, Last, BufferNumber, Every, LastNew) have, and which of these modes returns immediately without waiting for a new frame from the camera?

Search the web and cite the URL of every source you used.

## Answer

I could only partly settle this. The sources give numeric values for three of the five modes. I found no source for the values of Every and Last New.

**Numeric values**

| Mode | Value | Source |
|---|---|---|
| Next | 0 | Implied by the `NIIMAQdx.h` enum |
| Last | 1 | Implied by the `NIIMAQdx.h` enum |
| BufferNumber | 2 | Implied by the `NIIMAQdx.h` enum |
| Every | Not found | — |
| LastNew | Not found | — |

- **Next, Last, BufferNumber:** a copy of NI's `NIIMAQdx.h` declares `IMAQdxBufferNumberModeNext, IMAQdxBufferNumberModeLast, IMAQdxBufferNumberModeBufferNumber` with no values written in, plus a guard value of `0xFFFFFFFF`. In C, unassigned members count up from 0, which gives 0, 1 and 2. This copy is old (a WPILib mirror) and doesn't list Every or LastNew at all (https://github.com/wpilibsuite/nivision/blob/master/cpp/include/Vision/NIIMAQdx.h).
- **Every, LastNew:** I searched NI docs, NI forums and pylablib and found nothing. NI's C API page and the documentation.help pages failed to load, and the NI knowledge-base article on Last vs Last New failed with a certificate error. My guess would be 3 and 4, but no source supports that. To confirm, check `NIIMAQdx.h` in your local NI-IMAQdx install, or right-click the Buffer Number Mode constant in LabVIEW and look at the ring values.
- **A separate set of numbers:** an NI employee explains that buffer numbers use only 24 bits, and the upper bits hold special markers such as "Next, Newest, Oldest, Every, Last New, None" (for example, 4294967294 = "Newest"). Those are sentinel buffer-number values, not the mode enum values above (https://forums.ni.com/t5/Machine-Vision/Random-Get-Image2-vi-timeout-error-1074360293-during-a-GigE/td-p/3805397).

**Which mode returns without waiting for a new frame**

- **Last** is the one mode documented as returning right away. The Get Image2 documentation says Last "will not wait for the next buffer but will instead return the last acquired buffer." Next is the default and waits for the next acquired buffer. BufferNumber waits for the exact buffer you ask for (https://www.ni.com/docs/en-US/bundle/ni-imaqdx-vi-ref/page/ni-imaqdx_vi_reference/imaqdx_get_image2.html; my fetch of that page didn't load the text, so this wording comes from search-result excerpts of it).
- **Every** returns the next image you haven't read yet. According to one NI forum answer, it only returns without waiting when that image is already in memory. This isn't an unconditional "never waits" (https://forums.ni.com/t5/Machine-Vision/Buffer-Mode-quot-Next-quot-and-quot-Every-quot-in-IMAQdx-Extract/td-p/4079556).
- **Last New:** the NI article comparing it with Last is https://knowledge.ni.com/KnowledgeArticleDetails?id=kA03q000001DwvoCAC, but I couldn't retrieve its text. From the name, Last New probably waits when no new frame has arrived since your last read, but I haven't confirmed that.
