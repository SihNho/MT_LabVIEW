## Question

In Windows PowerShell 5.1, if a string variable that contains embedded double-quote characters and spaces is passed as a single argument to a native executable (for example & prog.exe $s), does the program receive it as one intact argument?

Search the web and cite the URL of every source you used.

## Answer

I'm done researching. The answer is **no**. In Windows PowerShell 5.1, `& prog.exe $s` does not reliably deliver a string with embedded `"` and spaces as one intact argument. The quotes get stripped, and the argument can be split into several.

**What the sources show:**

1. **Microsoft documentation.** PowerShell's `about_Parsing` page says PowerShell 7.3 changed how the command line is built for native commands. It calls this "a **breaking change** from the Windows PowerShell 5.1 behavior." Under the new behavior, "strings with embedded quotes the quotes are now preserved." Its example uses `$a = 'a" "b'` and `TestExe -echoargs $a`, and shows `Arg 0 is <a" "b>` as the new, corrected result. The page names the 5.1-era behavior "`Legacy`." In that mode, to get quotes through you have to add your own escaping (for example `\"`) or use `--%`. https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_parsing

2. **`$PSNativeCommandArgumentPassing` exists only in 7.3 and later.** The preference-variables page says "PowerShell 7.3 changed the way it parses the command line for native commands" and that "`Legacy` is the historic behavior." 5.1 has no switch that turns the fix on. https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_preference_variables

3. **PowerShell GitHub issue #1995, "Arguments for external executables aren't correctly escaped".** A user passed `` "`"a`"" `` and expected the program's first argument to be `"a"`. The program received `a` with the quotes stripped. The issue was fixed only in PowerShell 7.x. https://github.com/PowerShell/PowerShell/issues/1995

4. **Third-party reports (not authoritative, but consistent with the above):**
   - https://github.com/DKJ-Solutions/dkj-claude-plugins/issues/2405: "a -Body with embedded quotes is split by PS 5.1 native-argument quoting."
   - https://github.com/amirlehmam/wmux/issues/247: a value containing quotes is truncated and the flags after it are dropped.
   - https://dev.to/onurkizildag/i-spent-4-hours-fighting-powershell-51-quoting-hell-to-make-exa-mcp-work-here-is-the-10-line-fix-2jf3: says that in 5.1 embedded quotes are stripped at the native-argument boundary and a variable holding the correct string can still be split.

**What I couldn't confirm:** None of the sources I fetched gives Microsoft's own output for a specific string under 5.1. The docs show only the fixed 7.3 output and describe 5.1 as the behavior that changed. So I can't cite exactly how a given `$s` will break (quotes stripped, split into N pieces, or merged with the next argument), only that it isn't passed through intact. The usual workarounds in 5.1 are escaping the embedded quotes as `\"` yourself, or using `--%`, as `about_Parsing` shows.
