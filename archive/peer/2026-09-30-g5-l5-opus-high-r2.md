## Question

In the LabVIEW NI-IMAQdx palette, what are the DEFAULT values of the 'Buffer Number Mode' input of IMAQdx Get Image2.vi and of the 'Wait for Next Buffer?' input of IMAQdx Grab2.vi when those inputs are left unwired, and what does that default mean for a display loop that runs slower than the camera?

Search the web and cite the URL of every source you used.

## Answer

I found the answer, but NI's official reference pages wouldn't render through my fetch tool, so I couldn't read the manual text myself. What follows comes from NI Community forum posts.

## Defaults when the inputs are left unwired

**IMAQdx Get Image2.vi, Buffer Number Mode: the default is `Next`.** A forum reply says: *"Use the default Buffer Number Mode, Next, for Get Image2. Do not wire Buffer Number In … [it] should be left unwired, for the 'Next' mode."* ([NI forum: Buffers output in IMAQdx](https://forums.ni.com/t5/LabVIEW/Buffers-output-in-IMAQdx/td-p/3644259)). In `Next` mode, "the driver waits for the next acquired buffer." In `Last` mode, it "does not wait … but instead returns the last acquired buffer" ([NI forum: Buffer Mode "Next" and "Every"](https://forums.ni.com/t5/Machine-Vision/Buffer-Mode-quot-Next-quot-and-quot-Every-quot-in-IMAQdx-Extract/td-p/4079556)).

**IMAQdx Grab2.vi, Wait for Next Buffer?: the default is `TRUE`.** One post says: *"If you make it true(default) it waits for the next buffer to be ready before sending image, other case it returns the Last acquired buffer"* ([NI forum: Quick question about grab function](https://forums.ni.com/t5/LabVIEW/Quick-question-about-grab-function-in-IMAQdx/td-p/3607125)). An older thread says the same about IMAQdx Grab.vi: it "defaults to TRUE … If you set it to FALSE it would reprocess the last valid buffered image" ([narkive: Imaqdx Grab in a while loop](https://natinst.public.imaq.general.narkive.com/4VcvjWY5/imaqdx-grab-in-a-while-loop)).

## What this means for a display loop slower than the camera

With either default, each call waits for a frame that arrives after the call is made. It does not work through the frames that were acquired while the loop was busy. Those frames are skipped.

- An NI employee gave an example (it was about IMAQdx Extract Image in NXG, which uses the same Next mode): if you last took buffer 5 and the driver has reached buffer 10 by the next call, *"it would wait for buffer 11"* ([NI forum](https://forums.ni.com/t5/Machine-Vision/Buffer-Mode-quot-Next-quot-and-quot-Every-quot-in-IMAQdx-Extract/td-p/4079556)). To get every frame you would use `Every` mode.
- For a slow display loop, this means:
  - The loop runs at its own speed and shows fresh images, not an old backlog.
  - Frames are dropped without any error.
  - Each iteration can also block for up to one camera frame period while it waits for the next frame.
- To detect drops, compare Buffer Number Out between calls. It counts frames (1, 2, 3, …) rather than cycling through the physical buffers, so a jump bigger than 1 means frames were missed ([Buffers output thread](https://forums.ni.com/t5/LabVIEW/Buffers-output-in-IMAQdx/td-p/3644259); [Quick question thread](https://forums.ni.com/t5/LabVIEW/Quick-question-about-grab-function-in-IMAQdx/td-p/3607125)).

## Limits of the evidence

- I tried to confirm both defaults on NI's official pages ([Get Image2 reference](https://www.ni.com/docs/en-US/bundle/ni-imaqdx-vi-ref/page/ni-imaqdx_vi_reference/imaqdx_get_image2.html), [Grab2 reference](https://www.ni.com/docs/en-US/bundle/ni-imaqdx-vi-ref/page/ni-imaqdx_vi_reference/imaqdx_grab2.html)). Both returned only the site navigation. The documentation.help mirrors returned HTTP 403, and the [NI KB article on Last vs Last New](https://knowledge.ni.com/KnowledgeArticleDetails?id=kA03q000001DwvoCAC&l=en-US) failed with a certificate error.
- The Grab default of TRUE has two sources: one post clearly about the IMAQdx Grab VIs, and one about the older IMAQdx Grab.vi rather than Grab2.vi. None of them quotes the official help for Grab2.
- The "wait for buffer 11" example is about Extract Image rather than Get Image2 itself. It is consistent with how the forums describe `Next` mode.
- To be certain for your installed version, check the Context Help for each VI in LabVIEW: it shows the default in parentheses next to the input.
