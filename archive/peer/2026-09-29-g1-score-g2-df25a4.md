QUESTION:
In LabVIEW, can the 'Enable automatic error handling' option (VI Properties > Execution) of one specific VI be switched off programmatically through VI Server? If so, give the exact class and property name. Is there also a global switch?

KNOWN ANSWER (verified on the machine / vendor files):

### Answer

**Yes**, it can be switched off programmatically for a specific VI via VI Server.

* **Class:** `VI` (VI Server class hierarchy: `Generic » VI`)
* **Property Name:** 
  * **Long / Display Name:** `Execution:Automatic Error Handling` (or `Automatic Error Handling`)
  * **Short Name:** `Auto Err Handling`
  * **Data Type:** Boolean (`False` to switch off; `True` to enable)
  * **Access:** Read/Write in the LabVIEW development environment while the VI is in edit mode (not running). It is unsupported in the LabVIEW Run-Time Engine and Real-Time OS.

---

### Is there also a global switch?

**No global runtime switch exists** to toggle automatic error handling across all existing VIs simultaneously at runtime. The setting is persisted as an execution property per-VI inside the VI binary.

However, two related global mechanisms exist:

1. **Global default for newly created VIs (IDE / INI):**
   * **IDE:** **Tools » Options » Block Diagram » Error Handling » Enable automatic error handling in new VIs** (uncheck to disable by default).
   * **Configuration file (`LabVIEW.ini`):** The token `defaultErrorHandlingForNewVIs = False` (often accompanied by `EnableAutomaticErrorHandling = False`).
   * *Limitation:* This only affects new, blank VIs created afterward; it does not alter existing VIs.

2. **Programmatic batch modification:**
   * To switch it off across all loaded VIs, you must iterate over the VI references (e.g., via `Application.AllVIsInMemory` or project items) and write `False` to each VI's `Auto Err Handling` property individually.

3. **LabVIEW Run-Time Engine (Built executables):**
   * Automatic error handling is inherently and globally disabled/unsupported in the Run-Time Engine.
