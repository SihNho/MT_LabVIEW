## Question

In Windows PowerShell 5.1, which character encoding does Get-Content use by default when it reads a text file that has no byte-order mark?

Search the web and cite the URL of every source you used.

## Answer

### Answer

In Windows PowerShell 5.1, `Get-Content` uses the **`Default`** encoding—the system's active **ANSI code page** (e.g., Windows-1252 on Western European/US Windows, CP949 on Korean Windows)—when reading a text file that has no Byte-Order Mark (BOM).

---

### Official Documentation & Sources

1. **Microsoft Learn: `about_Character_Encoding` (PowerShell 5.1)**  
   https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_character_encoding?view=powershell-5.1  
   > *"For cmdlets that read string data in the absence of a BOM:*  
   > *- `Get-Content` and `Import-PowerShellDataFile` uses the `Default` ANSI encoding. ANSI is also what the PowerShell engine uses when it reads source code from files."*  
   >  
   > *"`Default`: Uses the encoding that corresponds to the system's active code page (usually ANSI)."*

2. **Microsoft Learn: `Get-Content` (PowerShell 5.1)**  
   https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/get-content?view=powershell-5.1  
   > Under `-Encoding`:  
   > *"Specifies the type of encoding for the target file. The default value is `Default`."*  
   > *"`Default` Uses the encoding that corresponds to the system's active code page (usually ANSI)."*

---

### Important Implications & Traps

- **BOM-less UTF-8 files will be misinterpreted:** Windows PowerShell 5.1 does not auto-detect BOM-less UTF-8 when reading via `Get-Content`. Any non-ASCII bytes will be decoded using the active ANSI code page, producing mojibake / character corruption.
- **PowerShell 7+ differs:** Modern PowerShell (v6+) changed this default behavior to BOM-less UTF-8 (`utf8NoBOM`).
- **To safely read BOM-less UTF-8 in 5.1:** Specify `-Encoding UTF8` explicitly, or set `$PSDefaultParameterValues['Get-Content:Encoding'] = 'utf8'`.

---

### Cheap Verification Check

To check what ANSI code page `Default` resolves to on the current Windows machine, run:
```powershell
[System.Text.Encoding]::Default.WebName
# typically returns 'windows-1252' (or localized code page like 'ks_c_5601-1987' / 'cp949')
```
