## Q1. Creating `Not Equal?`, `And`, `Select`, `Wait (ms)` with New VI Object

**Style IDs.** The LAVA thread "New VI Object style list" (https://lavag.org/topic/14519-new-vi-object-style-list/) contains a full dump of the style ring, posted by vugie from the LabVIEW 2009 ring constant. The entries read verbatim:

| Primitive | Style ID |
|---|---|
| Not Equal? | 1105 |
| And | 1061 |
| Select | 1516 |
| Wait (ms) | 1302 |

**Class to pass.** No source I found states the required `vi object class` per primitive. The LabVIEW Wiki lists `Comparison` as a subclass of `Function` with class ID 16429 (https://labviewwiki.org/wiki/Comparison_class) and `Function` with its `Style` property (https://labviewwiki.org/wiki/Function_class). NI's tutorial shows the pattern of picking the class from the class-specifier constant and the style from the ring constant (https://www.ni.com/docs/en-US/bundle/labview/page/tutorial-adding-an-object-to-a-vi-using-vi-scripting.html), but it only demonstrates a For Loop. An NI forum thread notes that NI's own answer for hard-to-drop primitives is to create them in a template VI and copy them rather than drop by style (https://forums.ni.com/t5/LabVIEW/VI-Scripting-Input-for-style-in-quot-New-VI-Object-quot-function/td-p/3267356). Another thread recommends creating with a generic class and then casting with To More Specific Class (https://forums.ni.com/t5/LabVIEW/LabVIEW-VI-scripting-finding-out-quot-new-VI-object-quot/td-p/3932054).

**Nested diagram as owner.** No source explicitly states that a Loop's `Diagram` reference is a valid owner for New VI Object. The Nested Case Structure thread shows traversing each structure's `Diagram` and treating the containing diagram as the owner, but does not show a New VI Object call with it (https://forums.ni.com/t5/LabVIEW/VI-Scripting-Nested-Case-Structure/td-p/3712057). The `Loop.Diagram` property (ID 6361401) exists (https://labviewwiki.org/wiki/Loop_class). Evidence does not settle this.

**Stability across versions.** Not settled. Both NI threads above and the LAVA thread leave the question unanswered. The LAVA list is from LabVIEW 2009. The `Function.Style` property is read-only and the ring is known to be incomplete (https://forums.ni.com/t5/LabVIEW/VI-Scripting-Input-for-style-in-quot-New-VI-Object-quot-function/td-p/3267356).

## Q2. Switching `Equal?` to `Not Equal?` after creation

No such property was found. The `Comparison` class exposes only `Compare Aggregates?` (ID 635A800) per the LabVIEW Wiki (https://labviewwiki.org/wiki/Comparison_class). `Function.Style` is read-only (https://labviewwiki.org/wiki/Function_class), and the `Node` class has no Replace method (https://labviewwiki.org/wiki/Node_class). Nothing named `Comparison Mode` or `Operation` appears on either class. The evidence points to creating a new node instead.

## Q3. While Loop iteration terminal and Create Indicator

**Property.** `Loop.Loop Counter` (ID 6361400) "returns a reference to the loop counter" and is inherited by `WhileLoop` (https://labviewwiki.org/wiki/Loop_class, NI page https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/vi-server/generic/gobject/node/structure/loop/loopcounter.html). `WhileLoop.Loop End Ref` (ID 6362C00) returns the conditional terminal (https://labviewwiki.org/wiki/WhileLoop_class). A forum thread confirms LoopCounter and LoopEndRef as the way to locate these terminals (https://forums.ni.com/t5/LabVIEW/VI-Scripting-locate-loop-iteration-and-conditional-terminals/td-p/4344904).

**Create Indicator on a nested-diagram terminal.** `Terminal.Create Indicator` (ID 6349C02) "creates an indicator for the terminal and returns a reference to it" (https://labviewwiki.org/wiki/Terminal_class, NI page https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/vi-server/generic/gobject/terminal/createindicator.html). No source states a restriction to top-level diagrams, and no source shows it used on a loop counter. An NI thread on wiring a scripted While Loop's conditional terminal was resolved by an NI employee's attached VI, but the text does not name the method used (https://forums.ni.com/t5/LabVIEW/Wiring-the-conditional-terminal-of-a-while-loop-created-by/td-p/2115512). Not settled by documentation.

## Q4. UID to GObject Reference.vi, then cast to Terminal

No documented or forum-reported example of this exact route was found. The VI is a hidden gem in vi.lib\VIServer that returns an object reference from a UID; it fails with error 1055 in the run-time engine, and NI added that note in LabVIEW 2015 (https://forums.ni.com/t5/Hidden-Gems-in-vi-lib/The-VI-quot-UID-to-GObject-Reference-vi-quot-does-not-work-in/td-p/3429508). `GObject.UID` (ID 632A813) is stable for a saved object but can be reassigned after deletion (https://labviewwiki.org/wiki/GObject_class/UID_property). Casting a generic GObject reference downward with To More Specific Class is the standard forum-reported approach, with the advice to try successively specific classes until no error occurs (https://lavag.org/topic/13549-gobject-to-more-specific-class-from-class-id/). Combining the two with `Terminal` and `Create Indicator` is not reported anywhere I found.
