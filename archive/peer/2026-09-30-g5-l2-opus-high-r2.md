## Question

With NI-IMAQdx and a USB3 Vision camera, a program opens a camera session, writes new values to attributes such as Width/Height (ROI), ExposureAuto/ExposureTime or the acquisition frame rate, confirms them by reading back, and then closes the session. When the next IMAQdxOpenCamera (or IMAQdx Open Camera VI) call opens the same camera, what values do those attributes have, and why?

Search the web and cite the URL of every source you used.

## Answer

**Short answer:** it depends on the attribute. The sources point to two groups, but none of them tests this exact sequence (write, read back, close, reopen) on a USB3 Vision camera. The split below is pieced together from the documentation and forum posts, not from a direct test.

**1. Attributes stored in the camera file (.icd) go back to the values in that file.**
- NI's reference says `IMAQdxOpenCamera` "opens a camera, queries the camera for its capabilities, loads a camera configuration file, and creates a unique reference to the camera." The configuration lives in a camera file, which the VIs and functions use to configure the camera. [NI-IMAQdx Function Reference: IMAQdxOpenCamera](https://documentation.help/NI-IMAQdx-Function-Reference/imaqdxOpenCamera.html), [IMAQdx Open Camera VI](https://documentation.help/NI-IMAQdx-VI/IMAQdx_Open_Camera.html)
- An NI employee wrote: "IMAQdx saves the configuration to the default file everytime you click the Save button in MAX. This file is then used whenever the camera is opened in either MAX or LabVIEW/C/VB/etc." Their fix for keeping settings was to save them explicitly with the Read/Write Attributes VIs. [NI forum: saving camera settings with NI-IMAQdx](https://forums.ni.com/t5/Machine-Vision/saving-camera-settings-with-NI-IMAQdx/td-p/658253)
- The same NI employee said Open "will create a default ICD from the camera config if one does not exist." The original poster disputed this and said the Read Attributes VI created the file instead. [NI forum thread](https://forums.ni.com/t5/Machine-Vision/IMAQdx-Read-Attributes-vi-WRITES-icd-file-if-none-exists-AWFUL/td-p/2867638)
- Why: writing through a property node changes only the live session. None of the sources says that write also updates the .icd file. The next Open applies what the file holds, so Width/Height and any other stored attribute get the last saved values (from MAX Save or Write Attributes), not the values your program wrote.

**2. Attributes not stored in the .icd are not reapplied by IMAQdx.** They probably keep whatever the camera itself last held, at least until the camera loses power.
- An NI employee explained: "IMAQdx respects the camera's list of attributes that are to be persisted. If it's not in the icd file, then the camera vendor didn't mark it as streamable." MAX and Write Attributes save only "a small subset of all the attributes." [NI forum: save camera attributes](https://forums.ni.com/t5/Machine-Vision/save-camera-attributes/td-p/3177343?profile.language=en)
- In the same thread, a user reported that Gain was not written to the .icd, and "If I powercycle the camera I lose the settings." That suggests such values survive a close and reopen but not a power cycle. This is one user's observation, not documented behaviour.
- Teledyne confirms that not all camera settings are saved in the .icd and says you can add them by editing the file by hand. [Teledyne: configuring a NI-MAX .icd file](https://www.teledynevisionsolutions.com/support/support-center/technical-guidance/iis/configuring-a-ni-max-.icd-file-to-save-camera-settings)

**What the evidence doesn't settle:**
- **Which group each of your attributes is in.** That depends on your camera's own attribute list and which ones the vendor marked as savable. No source lists this for ExposureAuto, ExposureTime or the frame rate. You can check by opening the camera's .icd in `C:\Users\Public\Documents\National Instruments\NI-IMAQdx\Data` (location given in the Teledyne note and the NI search results).
- **Whether values in the file are always applied.** One user reported that on every connect, IMAQdx set two Basler attributes to 1.0 even though the .icd held 44 and 1.6. Nobody from NI explained it. [NI forum: IMAQdx incorrectly loading some attributes](https://forums.ni.com/t5/LabVIEW/IMAQdx-incorrectly-loading-some-attributes-from-icd-file/td-p/4223918)
- **NI's own current pages.** The ni.com VI pages load their content with JavaScript, the documentation.help pages returned 403, and the NI knowledge-base article on loading and saving .icd files failed a certificate check. The NI quotes above come from search-result excerpts and NI-employee forum posts, not from pages I read in full.
