## Failure 1: "our gate's bug, OCR whitespace noise"

**1. Strongest reason it is wrong.** The noise is not only whitespace. Of the four "gone" items, three are spacing, but one is a letter misread: "This wire is not connected to **anvthing**." against "**anything**" (`diag_c139_1_out.json:316` vs `diag_c139_1_run.log:11`). The baseline itself holds two "anvthing" items (`errorlist_expected_D1_ring_p3b2b_20261002_130007.json:122`).
- `norm()` only lowercases and drops non-alphanumerics (`tools/errorlist_check.py:315-316`); it does not fold v→y. So a whitespace-normalised diff would still report 2 new / 1 gone, and the gate would still fail.
- Only `norm_ocr` (`errorlist_check.py:322-332`), or the class-level `compare`, removes that pair.
- Also, `errorlist_check` lives at `tools/errorlist_check.py`, not `tools/bench/`.

**2. Alternative explanation.** No single item can be identified at all, by either method. `compare` (`errorlist_check.py:415-439`) matches items by class key, using the raw text plus the detail text, against counted entries. So "1 extra, 0 missing" proves that the class counts moved by exactly +1 "Unwired selector". It does not prove that each of the other 51 is the same object as before.
- A swap inside one class would be invisible. For example, w25415's second sink (t25557, "autofocus reseed flag") could add one loose-ends item while another one goes away.
- The arithmetic is sound: the counts sum to exactly 51 (`expected:16-90`), and missing = 0.
- Linking the extra item to Case #10465 is still inferred. The route that reads an item's uid is unbuilt (`errorlist_check.py:53`). The screenshot `bd_184749_after9.png` does show a True/False Case near the Reset Tracking logic with an apparently empty `?`, which fits the claim but proves nothing at this resolution.

**3. What would falsify it.**
- Any class count other than the selector differing between the 13:08 baseline read and this read, after `norm_ocr` folding.
- Or a second read of the same copy showing a different set of extras.

**4. Cheapest test, no LabVIEW needed.** Run `EC.class_counts(..., ocr=True)` over `errorlist_c139_1_bed_raw.json` and over the `_130834.json` baseline, then diff them. The claim holds only if the sole non-zero difference is `casestructurecasestructureunwiredselector: +1`. Then gate on `compare()`'s `extra`/`missing` (the script computes them already, `diag_c139_1_run.py:38`) and delete the raw Counter gate (`:36-37,45`). Don't "add whitespace normalisation".

## Failure 2: "no SubVI on the scratch → node-A cast fails → 1055"

**1. Strongest reason it is wrong (or at least not established).** This is the third 1055 with the same inferred cause (`build_opstopfromnode_v0.log:54`, `diag_c97_tools_t124b.log:14`, now `diag_c139_1_run.log:22`).

**3. What would falsify it.** On this same scratch, with a valid node at `Traverse(src_cls)[src_index]`, `loop_in("for", TGT, <wb index>, …)` still returns 1055.

**4. Cheapest discriminating test.** One call, no new node: `loop_in("for", TGT, <wb index>, (250,150), src_cls="ForLoop", src_index=0)`. The generator For FG already exists, and `Names=[]` creates no tunnels. Three outcomes:
