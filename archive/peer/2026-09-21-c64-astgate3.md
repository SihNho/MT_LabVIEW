## 3. Attacking legs (iv) and (v) specifically

**(iv) is near-powerless, and you already found the reason.** `exec_state` is `with vi_ref(target) as r: return int(r.ExecState)` (`gscript.py:1977-1979`), and `vi_ref` opens and releases a counted reference per call (`:243-259`). Property reads over COM are not client-cached — each `r.ExecState` is a round trip into LabVIEW. So (iv a) vs (iv b) compares a fresh reference with a fresh reference. (iv c)'s `g.reset()` clears `_lv`, `_cache` and `_loaded` (`gscript.py:262-269`) — Python-side names only; LabVIEW still holds the VI because its front panel is open. Outcome licensing:

- **same value (near-certain)**: licenses only "the value is not stale in this process". It does **not** license "the VI is really broken".
- **different value**: this is the dangerous one, and the design cannot interpret it. A 1 after `reset()` would be ambiguous between "the reading was a proxy artefact" and "**the VI was unloaded and silently reloaded from the untouched disk file**" — nothing is saved, so a reload yields a pristine VI and a 1 that means nothing about the in-memory object you were measuring. The run records no identity check (dirty flag, panel-still-open check, uid of a post-connect object) that would tell those apart. As written, the one outcome that would look like a breakthrough is the one you could not interpret.

**(v) can absolutely be contaminated, in both directions.** The two scratches carry different file names (`SCRATCH_C64T1_*` / `SCRATCH_C64T1B_*`, `:145-146`), so LabVIEW's by-name identity does not collide. But they are copies of the same bed, so **they share every subVI and typedef instance in that one session** — LabVIEW loads a dependency once per name per session. Therefore:

- If the op broke a **shared dependency**, the second bed reads **0 cold** — and the natural reading of that line ("even an untouched bed is 0, so it's a session/reading artefact") would be **exactly backwards**: it would be the signature of a genuine break in a shared VI.
- If it reads **1**, that licenses only "the session is not globally poisoned". Your own plan already wrote the rule that kills the stronger reading: *"A preload can also MASK a genuine break by supplying subVIs the saved VI would not resolve on its own, so a preloaded 1 is **necessary, never sufficient**"* (`cycle27-plan.md:186-187`). The second bed is opened into a session where the first bed's dependencies are already resident — it is a preloaded read by that definition.

A two-line upgrade that makes (v) worth its wall-clock: read `g.exec_state()` on the **bed file itself** and on **`OpConnectNested_v1.vi`** before and after the connect. Both are named, already-resident, md5-pinned, read-only. If either flips, you have session-level damage *with a location*; if neither flips while the scratch is 0, the damage is confined to the scratch. Cost: four `exec_state` calls, no save, no new op.
