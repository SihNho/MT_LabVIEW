## Question

On an NTFS volume in Windows, a file is deleted and a new file with the same name is then created in the same folder shortly afterwards. What creation timestamp does the new file have, and what is the mechanism called?

Search the web and cite the URL of every source you used.

## Answer

### Answer

1. **Creation Timestamp:** The new file receives the **creation timestamp of the original (deleted) file**, rather than the current time when the new file was created.
2. **Mechanism Name:** The mechanism is called **File System Tunneling** (or **File Name Tunneling** / **Tunneling**).

---

### Reasoning & Details

* **Purpose:** Windows implements tunneling to accommodate applications using atomic "safe save" patterns (e.g., writing changes to a temporary file, deleting the original target file, and renaming the temporary file to the original name). Without tunneling, every save operation would reset the file's creation timestamp and could break short (8.3) to long filename associations for legacy applications.
* **Cache Lifetime & Capacity:** By default, metadata for deleted or renamed files is cached for **15 seconds** (up to 1,024 entries). If a new file with the exact same name is created in that folder within this 15-second window, it inherits the cached creation date and short/long name mappings.
* **Registry Configuration:** The mechanism is governed under `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\FileSystem`:
  * `MaximumTunnelEntryAgeInSeconds` (DWORD): Lifetime of cached metadata (default: `15`).
  * `MaximumTunnelEntries` (DWORD): Maximum cache entries (default: `1024`). Setting this value to `0` disables tunneling entirely.
