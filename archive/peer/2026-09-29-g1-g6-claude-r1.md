## Question

On an NTFS volume in Windows, a file is deleted and a new file with the same name is then created in the same folder shortly afterwards. What creation timestamp does the new file have, and what is the mechanism called?

Search the web and cite the URL of every source you used.

## Answer

The new file gets the **old file's creation timestamp**, not the time it was actually created. The mechanism is called **file system tunneling**. It also exists on FAT.

- **What happens:** For a short time after a file is deleted or renamed, Windows keeps some of its metadata. If a file with the same name appears in the same folder within that time, it inherits that metadata. This covers the creation time and the link between the long filename and its 8.3 short name. So the new file looks as if it was created when the original was. ([thewincentral](https://thewincentral.com/windows-new-files-old-creation-date-file-system-tunnelling/), [Senturean](https://www.senturean.com/posts/19_04_13_windows-file-system-tunneling/))
- **Time window:** By default this only happens if the new file is created within 15 seconds of the deletion. ([MCSI Library](https://library.mosse-institute.com/articles/2022/05/windows-file-system-tunneling-in-digital-forensics/windows-file-system-tunneling-in-digital-forensics.html), [Un minion curioso](https://unminioncurioso.blogspot.com/2020/07/ill-be-back-in-15-seconds-or-maybe-not.html))
- **Changing it:** The window is set by the registry value `MaximumTunnelEntryAgeInSeconds` under `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem`. Tunneling can also be turned off from the registry. ([Forensix|Exchange](https://www.forensixchange.com/posts/19_04_13_windows-file-system-tunneling/), [A Fistful of Dongles](https://www.afodblog.com/2013/02/microsoft-file-system-tunneling.html))
- **Why it exists:** Many programs save a file by writing a temporary file, deleting the original and renaming the temporary one. Tunneling keeps the original creation date, since the user only edited the file. Raymond Chen's Microsoft blog post explains this, but it doesn't give the time window. ([The Old New Thing](https://devblogs.microsoft.com/oldnewthing/20050715-14/?p=34923))

**Caveat:** The Microsoft article I tried to open (KB 172190 on learn.microsoft.com) returned a 404. The 15-second default and the registry value name therefore come from third-party forensics sources that cite that article, not from Microsoft directly. They all agree with each other.
