## Question

In Windows PowerShell 5.1, which character encoding does Get-Content use by default when it reads a text file that has no byte-order mark?

Search the web and cite the URL of every source you used.

## Answer

In Windows PowerShell 5.1, `Get-Content` defaults to **`Default`** encoding—the system's active legacy **ANSI** code page (e.g., Windows-1252 on US/Western European Windows installations, CP949 on Korean installations)—when reading a text file without a Byte Order Mark (BOM).

---

### Details & Reasoning

1. **BOM detection behavior**: If a file begins with a recognized Unicode BOM (such as UTF-8 BOM `0xEF, 0xBB, 0xBF` or UTF-16LE BOM `0xFF, 0xFE`), `Get-Content` detects it and decodes using that Unicode format.
2. **Absence of a BOM**: When no BOM is present, `Get-Content` does **not** assume UTF-8. Instead, it falls back to the system's active ANSI code page (`[System.Text.Encoding]::Default`). Multibyte UTF-8 characters without a BOM will be misinterpreted or corrupted into mojibake.
3. **Contrast with PowerShell 7+**: In PowerShell (Core) 6+, the default encoding for reading and writing files without a BOM was changed to BOM-less UTF-8 (`utf8NoBOM`).
