## Question

On an NTFS volume in Windows, a file is deleted and a new file with the same name is then created in the same folder shortly afterwards. What creation timestamp does the new file have, and what is the mechanism called?

Search the web and cite the URL of every source you used.

## Answer

**Answer:** If the new file is created in the same folder within about **15 seconds** (the default) of the old one being deleted, it usually gets the **old, deleted file's creation timestamp**, not the time it was actually created. The mechanism is called **file system tunneling**.

**How it works**
- When a name is removed from a folder by a delete or rename, Windows saves that file's creation time and its long/short (8.3) name pair in a cache. When a name is added to the folder by a create or rename, Windows checks the cache and restores any match. ([afodblog](https://www.afodblog.com/2013/02/microsoft-file-system-tunneling.html), [Senturean](https://www.senturean.com/posts/19_04_13_windows-file-system-tunneling/))
- A Microsoft engineer, Raymond Chen, confirms that "the creation timestamp and short/long names of a file are taken from a file that existed in the directory previously." He explains it as compatibility with programs that save by writing a temp file, deleting the original, then renaming the temp file. His post does not give the time window. ([The Old New Thing](https://devblogs.microsoft.com/oldnewthing/20050715-14/?p=34923))
- It works on both NTFS and FAT and is on by default on NTFS volumes. ([MCSI Library](https://library.mosse-institute.com/articles/2022/05/windows-file-system-tunneling-in-digital-forensics/windows-file-system-tunneling-in-digital-forensics.html), [Un minion curioso](https://unminioncurioso.blogspot.com/2020/07/ill-be-back-in-15-seconds-or-maybe-not.html))

**Registry settings** (DWORD values under `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem`)
- `MaximumTunnelEntryAgeInSeconds` sets how long cache entries last. The default is 15 seconds.
- `MaximumTunnelEntries` limits the cache size. Setting it to 0 turns tunneling off. ([afodblog](https://www.afodblog.com/2013/02/microsoft-file-system-tunneling.html), [MCSI Library](https://library.mosse-institute.com/articles/2022/05/windows-file-system-tunneling-in-digital-forensics/windows-file-system-tunneling-in-digital-forensics.html))

**What the evidence doesn't settle**
- The 15-second default and the registry value names come from third-party forensics write-ups. I did not find a Microsoft Learn page stating them directly. Chen's post links to an older Microsoft KB article, which I did not fetch.
- The ForensixChange copy of the Senturean article now shows unrelated content, and the Senturean page itself refused my connection. I cite Senturean only because its text appeared in the search results.
- Only the creation time is tunneled. The modified and access times reflect the new file's actual activity.
- Recent coverage of the same behavior: [Windows Latest](https://www.windowslatest.com/2026/09/21/microsoft-engineer-explains-why-windows-can-give-a-brand-new-file-the-creation-date-of-a-file-you-already-deleted/), [WinCentral](https://thewincentral.com/windows-new-files-old-creation-date-file-system-tunnelling/).
