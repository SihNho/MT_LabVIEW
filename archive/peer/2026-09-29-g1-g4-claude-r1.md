## Question

In Windows PowerShell 5.1, when the standard output of a native executable is captured inside PowerShell (for example $x = & prog.exe | Out-String), which setting determines the character encoding used to decode those bytes, and what do you set so that UTF-8 output is decoded correctly?

## Answer

I've finished the search. Here's the answer.

**The setting is `[Console]::OutputEncoding`.** PowerShell uses it to turn a native program's stdout bytes into strings when it captures them. By default it matches the console's OEM code page (e.g. 437 on US-English systems), not UTF-8. So UTF-8 output comes out garbled.

**To decode UTF-8 correctly, set it before running the program:**

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$x = & prog.exe | Out-String
```

**`$OutputEncoding` does not do this.** It controls the other direction. The Microsoft 5.1 docs say it "determines the character encoding method that PowerShell uses when piping data into native applications", and that it "should align to the value of `[Console]::InputEncoding`." Setting it will not fix output that was already decoded wrongly. The usual advice is to set both to UTF-8 if you want UTF-8 going in and coming out.

**How strong the evidence is:**
- Microsoft's 5.1 `about_Character_Encoding` page only says `$OutputEncoding` "affects the encoding PowerShell uses to communicate with external programs." It does not say which setting decodes captured stdout.
- The clear statement that `[Console]::OutputEncoding` does the decoding comes from a third-party blog (hy2k.dev) and a PowerShell GitHub issue (#7233). The GitHub issue shows UTF-8 from Node.js being garbled because it was decoded with the OEM code page.
- The Microsoft docs I found don't contradict this, but they don't confirm it either.
