QUESTION:
With NI-IMAQdx and a USB3 Vision camera, a program opens a camera session, writes new values to attributes such as Width/Height (ROI), ExposureAuto/ExposureTime or the acquisition frame rate, confirms them by reading back, and then closes the session. When the next IMAQdxOpenCamera (or IMAQdx Open Camera VI) call opens the same camera, what values do those attributes have, and why?

KNOWN ANSWER (verified on the machine / vendor files):
They are back at the values from the camera's configuration, not the ones written in the earlier session: IMAQdxOpenCamera reloads the camera file (.icd in the NI-IMAQdx Data folder) or the camera defaults on every open, so attributes written in one session are lost when it closes. Measured: ROI 640x512 -> 1280x1024 again, ExposureAuto Off -> Continuous, ExposureTime 5555 -> 1909 us, frame rate 150 -> 90 Hz. The owning session must write them after opening, or the camera file must be changed (e.g. saved from MAX).
KEY POINTS: settings do NOT persist to the next session; open reloads the camera file (.icd) / defaults; write after open or save to the camera file

**Short answer:** The sources don't settle it for every attribute, but here is what they do support:

- **Attributes saved in the NI-IMAQdx camera file (`.icd`)** probably come back with the values stored in that file, not the values your program wrote. That happens if the file exists and the attribute is in it.
- **Attributes not in the file** are, as far as I can tell, not restored by IMAQdx. Most likely they keep whatever value the camera itself is holding. No source I found says this directly, so it's an inference.

**Why**

1. **Open Camera loads the camera file.** NI's documentation says IMAQdx Open Camera "opens a camera, queries the camera for its capabilities, loads a camera configuration file, and creates a unique reference to the camera." NI-IMAQdx uses that file to configure the camera and its supported attributes. ([documentation.help – IMAQdx Open Camera](https://documentation.help/NI-IMAQdx-VI/IMAQdx_Open_Camera.html), [NI docs – IMAQdx Open Camera](https://www.ni.com/docs/en-US/bundle/ni-imaqdx-vi-ref/page/ni-imaqdx_vi_reference/imaqdx_open_camera.html), [documentation.help – Configuring Your Camera](https://documentation.help/NI-IMAQdx/Configuring_your_camera.html)) I got this wording from search-result summaries because those pages blocked or failed a direct fetch.

2. **The file is only written when someone saves it.** An NI staff member wrote that IMAQdx saves the configuration to the default file "every time you click the Save button in MAX. This file is then used whenever the camera is opened." To save from your own program, you call IMAQdx Write Attributes. ([NI forum – saving camera settings with NI-IMAQdx](https://forums.ni.com/t5/Machine-Vision/saving-camera-settings-with-NI-IMAQdx/td-p/658253)) Writing an attribute and reading it back does not update the file. So on the next open, any attribute in the file is set back to the saved value, if the file exists.

3. **Only some attributes go into the file.** NI staff said IMAQdx only saves attributes that the camera vendor marked as streamable (`<Streamable>Yes</Streamable>`) in the camera's GenICam XML. That XML is in `C:\Users\Public\Documents\National Instruments\NI-IMAQdx\Data\XML`. ([NI forum – save camera attributes](https://forums.ni.com/t5/Machine-Vision/save-camera-attributes/td-p/3177343?profile.language=en)) Whether Width/Height, ExposureAuto/ExposureTime or the frame rate are in the file therefore depends on your camera model's XML. The sources can't answer that in general.

4. **Attributes not in the file stay in the camera's own memory.** Settings are held in the camera's volatile memory and are lost when the camera is powered off. To keep them across power cycles, the recommended fix is the camera's User Set feature, which stores them in non-volatile memory. ([NI forum – attributes reset on power cycle](https://forums.ni.com/t5/LabVIEW/Camera-attributes-reset-to-invalid-values-on-power-cycle/td-p/3733922), [save camera attributes](https://forums.ni.com/t5/Machine-Vision/save-camera-attributes/td-p/3177343?profile.language=en)) It follows that such an attribute would still hold your last written value on the next open, as long as the camera stays powered. No source confirms this directly.

**Other factors**

- **Driver bugs:** users have reported IMAQdx setting some attributes to defaults at connect time even though the `.icd` file held other values. Examples are a Basler camera where two attributes went to 1.0 every time, and MAX ignoring saved trigger settings. ([incorrectly loading attributes from .icd](https://forums.ni.com/t5/LabVIEW/IMAQdx-incorrectly-loading-some-attributes-from-icd-file/td-p/4223918), [settings ignored when opening .icd](https://forums.ni.com/t5/Machine-Vision/Some-settings-in-IMAQdx-icd-are-not-saved-some-are-ignored-when/td-p/4051311))
- **Locale bug:** an older case where Open Camera seemed not to read the config at all turned out to be a decimal-separator mismatch in the file. ([Open Camera does not set Video mode](https://forums.ni.com/t5/Machine-Vision/IMAQdx-Open-Camera-does-not-set-Video-mode-which-should-be-read/td-p/1037168))
- **Missing file:** an NI employee said Open creates a default `.icd` from the camera's current configuration if none exists. Another user disputed this in the same thread. ([Read Attributes writes .icd thread](https://forums.ni.com/t5/Machine-Vision/IMAQdx-Read-Attributes-vi-WRITES-icd-file-if-none-exists-AWFUL/td-p/2867638))

**What's still unknown:** for your camera, you'd need to check two things. First, which of these attributes are in its `.icd` file under `...\NI-IMAQdx\Data`. Second, whether they're marked streamable in its XML. The sources don't give an answer that covers all cameras.
