## Question

In NI-IMAQdx (C function IMAQdxGetImageData, or the LabVIEW IMAQdx Get Image2 VI), what numeric value does each buffer-number mode (Next, Last, BufferNumber, Every, LastNew) have, and which of these modes returns immediately without waiting for a new frame from the camera?

Search the web and cite the URL of every source you used.

## Answer

I could only confirm three of the five numeric values. The web sources settle Next, Last and BufferNumber, but not Every or LastNew.

**Numeric values**

| Mode | Value | Status |
|---|---|---|
| Next | 0 | Confirmed |
| Last | 1 | Confirmed |
| BufferNumber | 2 | Confirmed |
| Every | not found | Unknown |
| LastNew | not found | Unknown |

- **The first three:** the `NIIMAQdx.h` header mirrored in wpilibsuite/nivision lists `IMAQdxBufferNumberModeNext`, `IMAQdxBufferNumberModeLast` and `IMAQdxBufferNumberModeBufferNumber` in that order with no explicit values, which in C makes them 0, 1 and 2. The only other member is `IMAQdxBufferNumberModeGuard = 0xFFFFFFFF`. pylablib's Python copy of the definitions writes the values out explicitly as `_int32(0)`, `_int32(1)` and `_int32(2)`.
- **Every and LastNew:** neither header version I found defines them. Searches for `IMAQdxBufferNumberModeEvery` and `IMAQdxBufferNumberModeLastNew` returned nothing that defines them. NI's own C and VI reference pages load their content with JavaScript and came back empty, and the NI PDF I downloaded couldn't be read. To get these two values, check the `niimaqdx.h` installed with your NI-IMAQdx version, or right-click the Buffer Number Mode input in LabVIEW and create a constant to see the enum.

**Which mode returns immediately**

- **Last** is the only mode I found documented as not waiting. An NI forum thread about LabVIEW NXG's IMAQdx Extract Image VI describes it as: "The driver does not wait for the next buffer but instead returns the last acquired buffer."
- **Next** waits for the next buffer to be acquired. The same thread and a separate NI forum thread about Get Image2 say this.
- **BufferNumber** waits for the exact buffer number you give it. This comes from a search-result summary; I didn't read it on an NI page.
- **Every** returns all sequential images in memory, according to the NXG thread. The thread says it returns frames that were already acquired without waiting. It doesn't say what happens when no unread frame is waiting, so it isn't confirmed to return immediately.
- **LastNew** is covered by an NI Knowledge Base article on the difference between Last and Last New, but every attempt to fetch it failed with a certificate error. Its wait behavior is unconfirmed, and I won't guess it.

One caveat: the Last and Next descriptions come from an NI forum thread about the NXG Extract Image VI, not the NI reference page for Get Image2. They agree with NI's wording as far as I can tell, but I couldn't check them against the official page.
