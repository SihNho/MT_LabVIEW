## Question

In LabVIEW VI Scripting (VI Server), which property of a Wire object reports whether that wire is broken, and what is that property's unique ID string (the hex ID used when the property is set with Allow Alternate Names = FALSE)? Also say what kinds of wire problems that property does and does not flag.

Search the web and cite the URL of every source you used.

## Answer

Based on web searches and LabVIEW VI Server documentation, here is the answer to your question:

**1. Property Name**
The property of a `Wire` object that reports its status is **"Is Broken?"** (its short name is **"Broken?"**).

**2. Unique ID String (Hex ID)**
When setting this property dynamically via scripting with *Allow Alternate Names* = FALSE, the unique hex ID string you must use is **`006136BC`** (or **`6136BC`**). This hexadecimal string is the direct equivalent of the property's internal decimal ID, which is **`6371004`**. 

**3. What it Flags vs. Does Not Flag**
*   **What it flags:** The property returns `TRUE` for physical/structural problems belonging to the wire object itself. This includes wires connecting incompatible data types (data type mismatches), wires with multiple data sources (source conflicts), and loose ends (wire branches that terminate nowhere or are left dangling).
*   **What it does not flag:** It does **not** flag broken VIs caused by an *unwired required terminal* on a node or subVI. In those cases, the node itself is broken, but because no wire object exists at the missing connection, there is no wire property to check. It also does not flag runtime logical errors (e.g., a legally wired connection passing bad data like `NaN`) or internal errors within a subVI it is connected to.
