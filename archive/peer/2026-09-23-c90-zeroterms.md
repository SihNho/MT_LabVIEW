## Answer

## (1) The strongest competing mechanism — and then the verdict on it

**Competing mechanism: `Terms[]` is NOT empty; it returns a 2‑element array whose elements are references to terminal objects that `move_in` destroyed, so `Index Array[0]` hands the six downstream nodes a dead reference.** This is not a doubt, it is a complete alternative that reproduces every column you measured:

- `Index Array` out of range **does not error** — it returns the type default, `Not A Refnum` for a refnum array. The 1055 is raised one link later and 1055 is **"Object reference is invalid"** (hex 0x41F), a statement about *the reference handed in*, not about an index ([NI KB](https://knowledge.ni.com/KnowledgeArticleDetails?id=kA00Z0000019L75SAE)). An **in‑range element that is itself an invalid refnum produces the identical result** — same null arriving at the same six nodes.
- `errT` staying clean is consistent with both: under my mechanism the array read genuinely succeeds, so of course the `Terms[]` node reports nothing.

So as argued, **the claim does not follow from its evidence.** "errT clean + six 1055 at index 0" is not a measurement of array length; the run never read a length. Note this is the *second* time the project has leaned on this inference — `archive/peer/2026-09-22-c88-walk-1055.md:71` made the same objection about the same op, and its "free companion check" was recorded **NOT RUN** (`:136-138`).

**But I then tested my own mechanism against your record, and it fails.** NI documents the ordering of this property: *"The first reference is the source if a source exists. The other references on the list are in no particular order"* ([NI, `Terminals[]`](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/vi-server/generic/gobject/wire/terminals.html)).

- Nine intact wires read on this same bed put the **source at index 0, 9 for 9** — `diag_c90b_coverage.log:35,45,55,65,75,85,95,124,134`. That includes `w7448`, an original hand‑drawn wire, not only script‑drawn ones.
- `w7337`'s only row is at **index 0 with `is_source=False`** (`diag_c90_endpoints.log:51`). Its source end was `#10407 t4 VISA out`, on a moved node (`docs/m3a1-severed-rows.md:52`).

Under my mechanism the dead source would still occupy slot 0 and index 0 would read 1055. It didn't — the surviving **sink** moved into slot 0. **Detached terminals vacate the list.** That is the discriminator, and it is already in your logs.

**Verdict, stated explicitly as the dispatcher requires: the zero‑terminals reading survives.** What would change my mind is `w7337` on the clean predecessor showing sink‑at‑index‑0 as well (which would make the ordering argument an artefact rather than evidence).
