QUESTION:
In LabVIEW VI Scripting, a program enumerates the objects on a block diagram and reads each object's class name (for example with Traverse for GObjects.vi or the ClassName property of a GObject reference). What class name does a VISA Write function node report, is there a VISA-specific scripting class for it, and how would a program pick out only the VISA Write nodes?

KEY POINTS: class = Function (generic); no VISA-specific class; identify by name/label 'VISA Write'

The sources I could reach don't settle this. I found no page that directly says what class name a VISA Write node reports, and no worked example of filtering for VISA Write. Here is what the evidence supports, and where it stops.

**1. What class name does VISA Write report?** It is a built-in function rather than a subVI. NI's help page calls it the "VISA Write Function" ([rajsite mirror of the LabVIEW help](https://rajsite.github.io/unofficial-lvdocs/lvinstio/VISA_Write.html)). In the scripting class tree, built-in functions sit under the class `Function` (ClassID 16400). `Function` has these direct subclasses: `ArrayToCluster`, `Comparison`, `FileDialog`, `FlattenUnflattenString`, `GPIBReadWrite` (ClassID 16433), `ReadWriteFile` and `TypeCast` ([LabVIEW Wiki – VI Server Class Hierarchy](https://labviewwiki.org/wiki/VI_Server_Class_Hierarchy)). So VISA Write reports either `Function` or one of those subclasses. I found nothing that says which.

**2. Is there a VISA-specific scripting class?** The hierarchy has no node class with "VISA" in its name. The only VISA classes are for controls and constants: `VISAResourceName` and `VISAResourceNameConstant` ([LabVIEW Wiki – VISAResourceName class](https://labviewwiki.org/wiki/VISAResourceName_class)). The one candidate is `GPIBReadWrite`. Its only property is "Synchronous I/O?" ("If TRUE, performs synchronous I/O…") ([LabVIEW Wiki – GPIBReadWrite class](https://labviewwiki.org/wiki/GPIBReadWrite_class)). VISA Write has exactly that setting: right-click, then Synchronous I/O Mode»Synchronous ([VISA Write help](https://rajsite.github.io/unofficial-lvdocs/lvinstio/VISA_Write.html)). That match suggests VISA Read/Write may report `GPIBReadWrite`, but I found no source confirming it. If it's true, GPIB Read/Write and VISA Read would probably report the same class, so the class name alone would not isolate VISA Write.

**3. How to pick out only VISA Write nodes.** No public, documented property I found says which built-in function a `Function` node is:
- The wiki lists four `Function` properties: Terminals Visible?, Style, Has Side Effects? and Resource Id ([LabVIEW Wiki – Function class](https://labviewwiki.org/wiki/Function_class)).
- Resource Id is marked Private, write-only, U32 ([LabVIEW Wiki – Resource Id property](https://labviewwiki.org/wiki/Function_class/Resource_Id_property)), so it isn't a documented way to read the function's identity.
- Outside LabVIEW, primitives in the saved VI file carry a numeric `primResID` ([lvkit issue #103](https://github.com/pragmatest-dev/lvkit/issues/103)). That is a file-format detail, not a scripting property.
- Traverse for GObjects returns references to every object of a class you name, including inside structures ([LabVIEW Artisan – The Power of Traverse](http://labviewartisan.blogspot.com/2009/06/labview-scripting-tip-1-power-of.html); [NI forum – Scripting, reference all objects](https://forums.ni.com/t5/LabVIEW/Scripting-Reference-all-objects-traverse/td-p/3811133)).

A plausible approach, which I have not verified:
- Traverse the block diagram for `GPIBReadWrite`, or for `Function` if that returns nothing.
- Tell VISA Write apart from the others by something else, such as its label text or its terminals (VISA Write has a "write buffer" input and a "return count" output). The label route has a known catch: a node's label text can't be read until the label has been shown at least once ([LabVIEW Wiki – Node Label property](https://labviewwiki.org/wiki/Node_class/Label_property)).

The quickest way to settle it is to put one VISA Write on a test diagram and read its ClassName property. If it says `GPIBReadWrite`, add a GPIB Write and a VISA Read and check whether they report the same class.
