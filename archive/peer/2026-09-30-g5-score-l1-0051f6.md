QUESTION:
When LabVIEW is automated from another program through its ActiveX (COM) server, the VirtualInstrument object is used to control a VI. Which VirtualInstrument property tells the client whether that VI is broken (cannot run), what numeric values can that property take and what does each mean? Does the ActiveX VirtualInstrument interface also expose a separate 'is broken' Boolean?

KNOWN ANSWER (verified on the machine / vendor files):
The ExecState property (execution state enum): 0 = bad / broken (eBad, broken run arrow), 1 = idle / runnable (eIdle), 2 = running as top-level VI (eRunTopLevel), 3 = running as a subVI / reserved for running (eRunning). There is no separate IsBroken member on the ActiveX VirtualInstrument interface; ExecState = 0 is how brokenness is read.
KEY POINTS: property ExecState; 0 = broken (eBad); 1 = idle/runnable; 2 and 3 = running; no separate IsBroken member

The property is **`ExecState`**. A value of **0 (`eBad`)** means the VI is broken and can't run. The sources I could read don't mention a separate "is broken" Boolean, but I couldn't load the full list of properties, so I can't rule one out.

**The property.** NI's reference has a page for `ExecState` under the ActiveX VI properties ([NI ExecState page](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/activex/vi/execstate.html)). The page didn't load for me; only the menus came back, so I'm relying on its URL and search result for that. Real client code reads it as `VI.ExecState` and compares it with `ExecStateEnum.eIdle`, `.eRunning` and `.eRunTopLevel` ([SECI LabViewApp.cs](https://shadow.nd.rl.ac.uk/SECI/html/LabViewApp_8cs_source.html)). It is the ActiveX version of the VI Server property `Execution:State` (short name `Exec.State`). That property is a read-only U32 enum and is available in the Run-Time Engine ([rajsite mirror of NI help](https://rajsite.github.io/unofficial-lvdocs/lvprop/VI_ExeState.html), [LabVIEW Wiki](https://labviewwiki.org/wiki/VI_class/Execution.State_property)).

**Values** (numbers and meanings from the two pages just cited):

| Value | ActiveX name | Meaning |
|---|---|---|
| 0 | `eBad` | "VI has errors and cannot execute" (broken) |
| 1 | `eIdle` | "VI is not running but is in memory" |
| 2 | `eRunTopLevel` | "VI is the top-level VI in an active hierarchy" |
| 3 | `eRunning` | "VI is reserved for execution by one or more active top-level VIs" |

One caveat on the numbers: no page I read lists the ActiveX names next to their numbers. I got the names from the SECI code and the numbers from the VI Server docs. Another project, which drives LabVIEW from outside, independently reports ExecState 0 for a broken VI and 1 for a working idle one, which matches rows 0 and 1 ([Zuehlke/labview-mcp PR #60](https://github.com/Zuehlke/labview-mcp/pull/60)). I found no outside confirmation of 2 and 3 for ActiveX specifically.

**A separate "is broken" Boolean?** The evidence doesn't settle this.
- NI's full list of ActiveX VI properties returned no content, and a mirror of it returned HTTP 403. So I couldn't check every property name ([NI VI Properties (ActiveX)](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/activex/vi-p.html), [documentation.help mirror](https://documentation.help/NI-ActiveX-LabView/VirtualInstrument_Class.html)).
- None of the sources I read mentions a Boolean for this. The Zuehlke PR calls ExecState "the only cheap check that sees this failure." In a LAVA forum thread, someone discovered a broken VI through its "bad" execution state and then opened its front panel to find the reason ([LAVA "Why is my VI Bad?"](https://lavag.org/topic/14744-why-is-my-vi-bad/)).

So in practice you check for broken with `ExecState == eBad` (0).
