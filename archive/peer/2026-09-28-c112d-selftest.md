## Answer

## 1. The strongest reason the claim is wrong: case J tests code that no longer exists

- The test stubs the old creator route. `selftest_stagekit.py:322-330` replaces `K.mod("diag_s3b_l0_localname_v2").create_local` with `_L.create_local`, which appends to `got`. J1 passes only if `got == [("plot ring (display)", 1)]` (`:336-337`).
- In cycle 102 `stagekit.create_local_read` stopped using that route. It now calls `g.create_local_read(self.work, panel_index)` (`tools/stagekit.py:687-697`, reaching `gscript.py:4139` → `_create_local_mode`). Nothing calls `_L.create_local` any more, so `got` stays `[]` and J1 fails. J2 then does `got[-1]` on the empty list, which is the `IndexError` in the log (`selftest_stagekit_c112d.log:73-80`).
- The run you cite as the good baseline was taken before that change. `selftest_stagekit_c101-5_dry2.log:73` shows the detail `"'plot ring (display)' panel[1]"`, without the `(READ mode)` suffix that `stagekit.py:697` produces now. The c112d log does show `(READ mode)`. So dry2 is not a baseline for the current code; it tested the older function.
- Under `--dry`, J1 still fails. The fake gscript turns `g.create_local_read` into `_stub`, which returns a `Fake` object (`stage_prerun.py:455-461, 514-520`). `_L.create_local` is still never called, so `got == []`. The `Fake` also fails the `r.get("is_source") != [True]` check at `stagekit.py:694`. Expect roughly 49 pass / 2 fail with `'s': 0.0`, not 51/0.
- On (b), the direct run is the intended form. Every run from 2026-09-22 to 09-24 was `py -u tools/bench/selftest_stagekit.py` run directly (`selftest_stagekit.log:1,56,…,637`), and the docstring promises "Nothing here opens COM" (`:1-2`). Since cycle 102, case J breaks that promise: it reaches real COM with `target="stub.vi"`, which gives error 7 after 14 s. The dry harness hid this, and the only dry runs on record predate cycle 102. So yes, it is a latent defect: the test lost its isolation from real COM when cycle 102 changed the creator route and the test was never updated.
