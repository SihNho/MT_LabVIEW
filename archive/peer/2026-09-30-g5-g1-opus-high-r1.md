## Question

In LabVIEW VI Scripting (VI Server), which property of a Wire object reports whether that wire is broken, and what is that property's unique ID string (the hex ID used when the property is set with Allow Alternate Names = FALSE)? Also say what kinds of wire problems that property does and does not flag.

Search the web and cite the URL of every source you used.

## Answer

I found the property and its ID. The second half of your question isn't settled by any public source I found.

**Property:** Wire class → **Is Broken?** (short name "Broken?"). It is read-only, returns a Boolean, and belongs to VI Scripting. The LabVIEW Wiki describes it as: "Returns TRUE if the wire is broken or in a bad state." It was added in LabVIEW 2018 and is not available in the Run-Time Engine or on RT targets. ([Is Broken? property](https://labviewwiki.org/wiki/Wire_class/Is_Broken%3F_property))

**ID string: `6371004`**
- The Wiki gives the ID as `6371004`. The Wire class's other property IDs run in sequence from `6371000` to `637100E`. Because they include the letters A–E, these IDs are hexadecimal strings, not decimal numbers. ([Wire class](https://labviewwiki.org/wiki/Wire_class))
- One page summary I received claimed the ID was "0x612ABC". That value doesn't appear on the page; the summarizing tool made it up. I checked the page's exact text and it shows only `6371004`.
- The scripting method **Set Properties()** takes `ID Strings[]` plus an optional **"Allow Alternate Names? (F)"** input. That matches the setup you described. ([Set Properties() method](https://labviewwiki.org/wiki/Property_class/Set_Properties()_method))
- No source says outright that the Wiki's "Property ID" is the same value you pass as the Unique ID string. It is very likely, though: other examples of these ID strings have the same form, such as `636F80E` ([All Supported Properties](https://labviewwiki.org/wiki/Property_class/All_Supported_Properties_property)) and `632d809` ([LAVA thread](https://lavag.org/topic/18838-scripting-property-node/)). To confirm, read **All Supported Properties** on a Wire-class Property Node and check its Unique ID column.

**What it does and does not flag: unknown.** The only description I found is the one sentence "broken or in a bad state." The Wiki page doesn't list which wire problems count, and NI's own pages for this property wouldn't load. I found no forum post that tested it either. Here is what is documented around it:
- LabVIEW's wiring errors include a wire with no source, a wire with more than one source, and type conflicts. None of these pages is tied to Is Broken?. ([Wiring Errors](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/errors/wiring-errors.html), [wire has no source](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/errors/wire-has-no-source.html), [wire has multiple sources](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/errors/wire-has-multiple-sources.html))
- The docs for the Wire **Terminals[]** property say that if more than one source is listed, "the wire is broken." ([Terminals[]](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/vi-server/generic/gobject/wire/terminals.html))

It is plausible that Is Broken? matches the broken-wire display (dashed line with a red X), but I found nothing that confirms it. I also found nothing on whether it reports loose wire ends that the editor still accepts, or diagram errors that aren't wiring errors. The dependable way to find out is to build test VIs with each kind of fault and read the property on each.
