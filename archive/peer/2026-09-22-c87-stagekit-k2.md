## 4. Cheapest discriminating test

~2 seconds, no LabVIEW, no lock, no rig — it separates "one wrong string" from "two uncoordinated owners":

```
py -c "import sys,os; [sys.path.insert(0,p) for p in ('tools','tools/bench','tools/recipes')]; \
import stagekit as K, diag_s2_scaffold as D, build_opfsinnertunnelconnect_v0 as C82; \
print('same object:', K.ORIGINAL is D.ORIGINAL, C82.PINS[0][1] is D.ORIGINAL); \

```

`is` is the discriminator **on purpose**, as a provenance test rather than an equality test: `os.path.join` builds its result at runtime and CPython interns only compile-time literals, so two equal-but-separately-typed paths are never `is`-identical ([stackabuse](https://stackabuse.com/guide-to-string-interning-in-python/), [python-reference](https://python-reference.readthedocs.io/en/latest/docs/functions/intern.html)). Today line 1 prints `False` while line 2 prints `True` — your fix made them *equal*, my point is that they are still two objects that can drift apart again. After moving the constant into `gscript.py` and importing it in both places, line 1 prints `True True`, and the same two expressions become the missing self-test case (`case_g_constants`, ~5 lines, no LabVIEW) so this cannot ship again.
