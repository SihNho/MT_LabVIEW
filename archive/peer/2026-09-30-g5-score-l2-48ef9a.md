QUESTION:
With NI-IMAQdx and a USB3 Vision camera, a program opens a camera session, writes new values to attributes such as Width/Height (ROI), ExposureAuto/ExposureTime or the acquisition frame rate, confirms them by reading back, and then closes the session. When the next IMAQdxOpenCamera (or IMAQdx Open Camera VI) call opens the same camera, what values do those attributes have, and why?

KNOWN ANSWER (verified on the machine / vendor files):
They are back at the values from the camera's configuration, not the ones written in the earlier session: IMAQdxOpenCamera reloads the camera file (.icd in the NI-IMAQdx Data folder) or the camera defaults on every open, so attributes written in one session are lost when it closes. Measured: ROI 640x512 -> 1280x1024 again, ExposureAuto Off -> Continuous, ExposureTime 5555 -> 1909 us, frame rate 150 -> 90 Hz. The owning session must write them after opening, or the camera file must be changed (e.g. saved from MAX).
KEY POINTS: settings do NOT persist to the next session; open reloads the camera file (.icd) / defaults; write after open or save to the camera file

**Short answer:** On the next open, attributes that are saved in the camera's `.icd` file most likely go back to the values in that file. Your written values are not kept unless you saved them to that file. Attributes that are not in the `.icd` are not reloaded; they probably keep whatever the camera still holds until it is power-cycled. NI's reference docs never say this outright. It comes from NI's one-line description of Open Camera plus NI forum posts, and I did not find any source that tested your exact sequence.

**What the sources support**

1. **Open Camera loads a configuration file.** NI describes IMAQdx Open Camera / `IMAQdxOpenCamera` as opening the camera, querying its capabilities, loading a camera configuration file and creating a reference. I only saw this in search-result summaries because the doc pages returned 403 when I fetched them.
   - https://documentation.help/NI-IMAQdx-VI/IMAQdx_Open_Camera.html
   - https://documentation.help/NI-IMAQdx-Function-Reference/imaqdxOpenCamera.html
2. **That file is the per-camera `.icd`, used by MAX and by LabVIEW/C.** An NI forum answer says IMAQdx saves to the default file each time you click Save in MAX, and "this file is then used whenever the camera is opened in either MAX or LabVIEW/C/VB/etc." Another user reports that LabVIEW loads the camera settings from the `.icd` in `C:\Users\Public\Documents\National Instruments\NI-IMAQdx\Data` when it connects.
   - https://forums.ni.com/t5/Machine-Vision/saving-camera-settings-with-NI-IMAQdx/td-p/658253
   - https://forums.ni.com/t5/LabVIEW/IMAQdx-incorrectly-loading-some-attributes-from-icd-file/td-p/4223918

3. **The file changes through MAX's Save or IMAQdx Write Attributes, or on first open.** To keep settings you change in your own program, NI points to Write Attributes / Read Attributes. An NI employee said Open creates a default `.icd` from the camera's current configuration if none exists.

4. **Only "streamable" attributes go in the `.icd`.** An NI employee: "IMAQdx respects the camera's list of attributes that are to be persisted. If it's not in the icd file, then the camera vendor didn't mark it as streamable." The list comes from the camera's GenICam XML (`<Streamable>Yes</Streamable>`), cached under `...\NI-IMAQdx\Data\XML`. The same thread notes that settings not in the file are lost when the camera is power-cycled.
   - https://forums.ni.com/t5/Machine-Vision/save-camera-attributes/td-p/3177343
   - https://www.teledynevisionsolutions.com/support/support-center/technical-guidance/iis/configuring-a-ni-max-.icd-file-to-save-camera-settings

**Why the values change**

Close ends the session but does not save anything to the `.icd`. The next open reads the `.icd` and writes its values to the camera, which overwrites what your program set in the previous session. The `.icd` also works as a "camera file" that MAX can overwrite.

**What the evidence does not settle**

- **Whether your camera saves these particular attributes.** Width/Height, ExposureAuto/ExposureTime and AcquisitionFrameRate are only reloaded if your camera's XML marks them streamable. You can check by opening your `.icd` and seeing whether they are listed.
- **Non-saved attributes.** For these, I found no statement about whether a close-then-reopen without a power cycle keeps your written value. "They keep the camera's current value" is an inference from the thread above.
- **Load problems.** The forum reports some values that are in the `.icd` still not being applied, or being reset on connect: Basler compression/scaling attributes, trigger settings, and a video-mode case caused by locale. So a value being in the file does not guarantee the camera ends up with it.
  - https://forums.ni.com/t5/LabVIEW/IMAQdx-incorrectly-loading-some-attributes-from-icd-file/td-p/4223918
  - https://forums.ni.com/t5/Machine-Vision/Some-settings-in-IMAQdx-icd-are-not-saved-some-are-ignored-when/td-p/4051311
  - https://forums.ni.com/t5/Machine-Vision/IMAQdx-Open-Camera-does-not-set-Video-mode-which-should-be-read/td-p/1037168
- **Exposure time with auto on.** If ExposureAuto comes back as Continuous, the camera sets the exposure time itself. I found no IMAQdx-specific source on this.

To get a firm answer for your camera, read the attributes back right after the next Open Camera and compare them with your `.icd`.
