QUESTION:
In LabVIEW, can the 'Enable automatic error handling' option (VI Properties > Execution) of one specific VI be switched off programmatically through VI Server? If so, give the exact class and property name. Is there also a global switch?

KNOWN ANSWER (verified on the machine / vendor files):
Yes: the VI class property 'Automatic Error Handling' (a writable Boolean on a VI reference) turns it off for that VI. A global alternative is the labview.ini key EnableAutomaticErrorHandling=False.
KEY POINTS: VI class property Automatic Error Handling; writable; global ini key EnableAutomaticErrorHandling

**Answer:** Yes. You can switch it off for one specific VI through VI Server. There is no confirmed global VI Server switch; the only global switches I found are in Tools»Options.

**Per-VI property**
- **Class:** VI (you get it from an Open VI Reference or This VI reference)
- **Property name:** `Automatic Error Handling`. The short name shown on a Property Node is `Auto Err Handling`.
- **Type and access:** Boolean, read/write, but it can't be set while the VI is running. TRUE turns on automatic error handling for that VI.
- Source: [LabVIEW Wiki – VI class/Automatic Error Handling property](https://labviewwiki.org/wiki/VI_class/Automatic_Error_Handling_property). NI's own page for it is [here](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/properties-and-methods/vi-server/vi/automaticerrorhandling.html), but it didn't render when I fetched it, so I couldn't check it against the wiki.

**Limits reported on NI's forums (not in official docs):**
- The property is said not to exist for polymorphic VIs such as DAQmx Read ([forum thread](https://forums.ni.com/t5/LabVIEW/How-to-disable-internal-error-handling/td-p/1802206)).
- The option is said not to apply in the Run-Time Engine (built applications) or in LabVIEW RT ([forum thread](https://forums.ni.com/t5/LabVIEW/Execution-properties-Enable-automatic-error-handling/td-p/2578241)).

**Global switches**
- **Tools»Options»Block Diagram** has two settings: "Enable automatic error handling in new VIs" and "Enable automatic error handling dialogs" ([NI Idea Exchange](https://forums.ni.com/t5/LabVIEW-Idea-Exchange/Ability-to-enable-or-disable-Automatic-Error-Handling-for-all/idi-p/4392260), [LabVIEW Wiki – Automatic Error Handling](https://labviewwiki.org/wiki/Automatic_Error_Handling)).
- The first one only affects VIs created afterwards, not existing ones ([forum thread](https://forums.ni.com/t5/LabVIEW/How-to-disable-internal-error-handling/td-p/1802206)).
- I couldn't find NI documentation describing exactly what the "dialogs" setting does, so I can't say for sure how it behaves.

**No bulk VI Server switch**
- An NI Idea Exchange request for a project-wide on/off was declined. NI pointed users to the third-party Property Inspector toolkit instead ([Idea Exchange](https://forums.ni.com/t5/LabVIEW-Idea-Exchange/Ability-to-enable-or-disable-Automatic-Error-Handling-for-all/idi-p/4392260)).
- An NI staff member (Darren) is quoted there saying it "does require tooling to enable or disable on an entire codebase".
- The LabVIEW Wiki also says VI Scripting tools exist for this ([LabVIEW Wiki](https://labviewwiki.org/wiki/Automatic_Error_Handling)).
- The usual workaround is to loop over the VIs and set the per-VI property on each one.

**INI key:** One user reported that adding `EnableAutomaticErrorHandling=False` to LabVIEW.ini had no effect ([forum thread](https://forums.ni.com/t5/LabVIEW/How-to-disable-internal-error-handling/td-p/1802206)). I found no official documentation for this key, so treat it as unconfirmed.
