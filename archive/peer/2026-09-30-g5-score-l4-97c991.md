In LabVIEW VI Scripting, a program enumerates the objects on a block diagram and reads each object's class name (for example with Traverse for GObjects.vi or the ClassName property of a GObject reference). What class name does a VISA Write function node report, is there a VISA-specific scripting class for it, and how would a program pick out only the VISA Write nodes?

**1. What class name does VISA Write report?**
- The strongest candidate is **`GPIBReadWrite`**, but no source confirms it. In the VI Server class hierarchy, `GPIBReadWrite` (ClassID 16433) is one of only seven direct subclasses of `Function` (ClassID 16400). The others are ArrayToCluster, Comparison, FileDialog, FlattenUnflattenString, ReadWriteFile and TypeCast. https://labviewwiki.org/wiki/VI_Server_Class_Hierarchy
- Its only property of its own is **"Synchronous I/O?"**: "If TRUE, performs synchronous I/O. If FALSE, performs asynchronous I/O." The wiki page is a stub and doesn't say which functions the class covers. https://labviewwiki.org/wiki/GPIBReadWrite_class
- The link to VISA is my inference. VISA Read and VISA Write are the nodes known to have a synchronous/asynchronous setting, chosen from the right-click menu under Synchronous I/O Mode. http://ideasinwiring.blogspot.com/2006/09/asynchronous-versus-synchronous-nodes.html and https://www.ni.com/en/support/documentation/supplemental/18/choosing-between-synchronous-and-asynchronous-ni-visa-functions.html
- If VISA Write isn't in that class, it would report the plain **`Function`** class, which is used for primitives. I couldn't confirm either case.

**2. Is there a VISA-specific scripting class?**
- None found for the function nodes. The only classes with "VISA" in the name are `VISAResourceName` (ClassID 50, under IOName) and `VISAResourceNameConstant` (ClassID 16448, under IONameConstant). These are the resource-name control and constant, not VISA Write. https://labviewwiki.org/wiki/VI_Server_Class_Hierarchy
- Even if VISA Write is a `GPIBReadWrite`, that class seems to be shared with other read/write functions. Filtering on the class name alone probably can't tell VISA Write from VISA Read (not confirmed).

**3. How to pick out only the VISA Write nodes**
No source gives a documented method. These are the building blocks the sources support:
- **Filter by class:** use Traverse for GObjects.vi with class name `GPIBReadWrite`, or `Function` if needed. https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/vi-lib/utility/traverseref-llb/traverse-for-gobjects-vi.html (this page didn't render for me, so I haven't seen its details).
