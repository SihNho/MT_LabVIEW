QUESTION:
In LabVIEW VI Scripting, a program reads the Nodes[] property of a block diagram (Diagram / TopLevelDiagram class) to enumerate what is on it. Does that array include diagram constants, structure tunnels (for example loop tunnels or case selector tunnels) and shift registers? If some of them are missing, why, and how can a program enumerate them instead?

KNOWN ANSWER (verified on the machine / vendor files):
No. Nodes[] returns only objects of the Node class. A diagram Constant is a GObject but not a Node, so it never appears; loop tunnels, case-selector tunnels and shift registers are not in Nodes[] either (they belong to their structure). To enumerate them use a GObject-level traversal, e.g. vi.lib's Traverse for GObjects.vi by class name (or the diagram's AllObjs[] / the structure's own tunnel and shift-register properties).
KEY POINTS: constants are NOT in Nodes[] (Constant is a GObject, not a Node); tunnels and shift registers are NOT in Nodes[]; use Traverse for GObjects / AllObjs[] / structure properties

**Short answer:** Nodes[] almost certainly leaves out ordinary diagram constants, all structure tunnels (loop tunnels and the case selector) and shift registers. The reason is that none of them are Node-class objects in LabVIEW's scripting class tree. I found no NI page that says so outright. The conclusion rests on the class hierarchy plus one forum statement, so it is well supported but not officially documented.

**What Nodes[] returns**
- The LabVIEW Wiki describes the property as "Returns references to all the nodes in the diagram." ([Nodes() property](https://labviewwiki.org/wiki/AbstractDiagram_class/Nodes()_property))
- A separate property, All Objects[], returns "all the top-level objects in the block diagram," which is a broader set. ([All Objects() property](https://labviewwiki.org/wiki/AbstractDiagram_class/All_Objects()_property))

**Where each object sits in the class tree** ([VI Server Class Hierarchy](https://labviewwiki.org/wiki/VI_Server_Class_Hierarchy))

| Object | Class path | Is it a Node? |
|---|---|---|
| Diagram constant | Generic > GObject > Constant ([Constant class](https://labviewwiki.org/wiki/Constant_class)) | No |
| Any tunnel | Generic > GObject > Tunnel ([Tunnel class](https://labviewwiki.org/wiki/Tunnel_class)) | No |
| Loop tunnel | GObject > Tunnel > LoopTunnel | No |
| Case selector | GObject > Tunnel > ConditionalTunnel > SelectorTunnel | No |
| Shift registers | GObject > Tunnel > LeftShiftRegister / RightShiftRegister | No |
| Structures, subVIs, functions | GObject > Node > … ([Node class](https://labviewwiki.org/wiki/Node_class)) | Yes |

An NI forum answer backs this up: "The LoopTunnel class is not a 'Node' or 'Control'." ([NI forum](https://forums.ni.com/t5/LabVIEW/How-to-change-tunnel-mode-using-vi-scripting/td-p/3969392))

Two exceptions: ControlReferenceConstant and StaticVIReference are listed as children of Node ([Node class](https://labviewwiki.org/wiki/Node_class)). So control-reference constants and static VI references should show up in Nodes[] even though they look like constants.

**Why tunnels and shift registers are missing:** they are owned by the structure's border, not by the diagram. You reach them through the structure object instead.

**How to enumerate them instead**
- **Tunnels:** read `Structure:Tunnels[]` ([Tunnels() property](https://labviewwiki.org/wiki/Structure_class/Tunnels()_property)). Each tunnel has `Outside Terminal` and `Inside Terminals[]`, with one inside terminal per frame ([Tunnel class](https://labviewwiki.org/wiki/Tunnel_class)). Use To More Specific Class to get a LoopTunnel, for example to change its indexing mode ([NI forum](https://forums.ni.com/t5/LabVIEW/How-to-change-tunnel-mode-using-vi-scripting/td-p/3969392)).
- **Shift registers:** read `Loop:Shift Registers[]` ([Shift Registers() property](https://labviewwiki.org/wiki/Loop_class/Shift_Registers()_property), [Loop class](https://labviewwiki.org/wiki/Loop_class)).
- **Case selector:** read `CaseStructure:Selector` ([CaseStructure class](https://labviewwiki.org/wiki/CaseStructure_class)).
- **Contents of structures:** read `Structure:Diagrams[]` to get each subdiagram, then query that subdiagram ([Structure class](https://labviewwiki.org/wiki/Structure_class)).
- **Everything at any depth:** use `Traverse for GObjects.vi` with a class name such as "Constant", "Tunnel", or "GObject" for all objects. It searches recursively. All Objects[] does not, and Traverse is described as much faster than recursing yourself. ([LabVIEW Artisan](http://labviewartisan.blogspot.com/2009/06/labview-scripting-tip-1-power-of.html), [NI forum: traverse](https://forums.ni.com/t5/LabVIEW/Scripting-Reference-all-objects-traverse/td-p/3811133), [NI forum: all references](https://forums.ni.com/t5/LabVIEW/LV-Scripting-how-to-get-all-diagram-object-references/td-p/2742296), [NI docs page](https://www.ni.com/docs/en-US/bundle/labview-api-ref/page/vi-lib/utility/traverseref-llb/traverse-for-gobjects-vi.html))
