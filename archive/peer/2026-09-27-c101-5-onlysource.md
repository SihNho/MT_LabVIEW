## 1. Strongest reason it is wrong
When SubVI #376 moved from diagram 639 to 23405, its outside sinks were **tunnel inner terminals**:
- 1931 on #1929 and 5044 on #5020 (`tools/bench/diag_c71_l7_1a_tunnels.log:32,36,60,64`).
- Both #1929 and #5020 are LoopTunnels (`tools/bench/c73_l7r_live.log:25`).
- Both **kept** their sourceless half-wires, w5274 and w5056 (`diag_c71_l7_1a_tunnels.log:70`, `half_wires_only_in_b`).

The sink-class rule predicts both should have been deleted. The constant case also counts against it:
- Sink 8753 is an ordinary IndexArray node terminal (`index (row)`, `owner_class IndexArray`, `frame_diagram 7911` in `tools/bench/sim/disp/step_03_create.json`).
- It was **deleted**, so the rule only survives with a special exception for constants.
- A rule that needs an exception to fit two samples is fitted to the data, not explained by it.

The source-class rule on the card fails too: BuildArray #11261 is a primitive, yet 8323 kept its half-wire at k24/k25.

## 2. Alternatives that fit every real observation with one rule
Only four observations are real LabVIEW reads.

| move | from diagram | to diagram | sink | fate |
|---|---|---|---|---|
| constant #8775 | 7911 (inside For loop #1359) | 23432 (For loop inside the new While, on 686) | 8753, IndexArray | deleted |
| Bundler #11310 (k12) | 7911 | 23432 | 11365, tunnel inner terminal | deleted |
| BuildArray #11261 (k22, read at k24/k25) | 639 (inside While loop #637) | 23073 (new While loop, on 686) | 8323, panel terminal | kept |
| SubVI #376 (c71) | 639 | 23405 (While loop #23041, on 686) | 1931 / 5044, tunnel inner terminals | kept |

Nesting, from the owner map in `step_03_create.json`: flat sequence frame 686 contains While #637, whose inside is diagram 639. For #1359 sits on 639 and its inside is 7911. The new loops all sit on 686.

Three single-rule alternatives, fully confounded in these four samples:
- **A. Where the node came from:** moving out of the For #1359 interior (7911) deletes; moving out of the While #637 interior (639) keeps.
- **B. Where the node went:** a destination that is a For loop two levels below 686 deletes; a While loop one level below keeps.
- **C. What kind of loop held the wire:** the wire lived inside For #1359, which the graph file name `par1359` suggests is a parallel For loop.

Clearing out the junk nodes (the stray Invoke Node each move leaves, purged afterwards) is ruled out. It runs identically after every move, and each deleted junk node had 0 wired terminals (`stage_d1_disp_r5.log:88,242,419`).

## 3. What would falsify each
- **Sink class:** already falsified by 1931 and 5044.
- **A:** a move out of 639 into a For interior that deletes, or a move out of 7911 into a While interior that keeps.
- **B:** the same two moves, with the opposite predictions.
- **C:** a delete where the wire was not inside a For loop.
